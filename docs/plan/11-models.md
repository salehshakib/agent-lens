# 11. Model and reasoning selection

[← 10](10-codex-controls.md) · [Plan index](README.md) · [12 →](12-accounts.md)

Use one model picker contract from both chat and run forms, backed by the active adapter. Offer default/inherit and explicit choices with source, profile, alias/full ID, supported effort list, and optional speed capability. Keep preferred defaults under <code>agentLens.agents</code> per adapter, with each run's override in the draft. A model or effort change affects the next eligible turn. Only offer in-channel switching when supported. Otherwise apply it on the next exact resume or retain the current native default. Display the **requested selection** separately from the **actual model/effort** read from the stream/settings/events after launch. Settings precedence, runtime restrictions and fallback models can change what actually ran.

| Adapter and source | Picker behavior and limits |
| --- | --- |
| Claude SDK or structured active session | Where using an authorized, compatible SDK session, use <code>Query.supportedModels()</code> and the documented initialization model list. Use <code>ModelInfo.value</code>, optional <code>resolvedModel</code>, <code>displayName</code>, <code>supportsEffort</code>, <code>supportedEffortLevels</code>, <code>supportsAdaptiveThinking</code>, <code>supportsFastMode</code>, and <code>supportsAutoMode</code>. Query within the user's selected trusted session. Startup can run hooks or MCP even without a prompt, so it must follow explicit chat initialization, not watch activation. [SDK model info and startup](https://code.claude.com/docs/en/agent-sdk/typescript) |
| Claude native CLI | Use a verified model catalog from the CLI-backed session if emitted. Installed help advertises <code>--model</code> with aliases and full names but has no public standalone model-list flag. The native <code>/model</code> menu is the account-aware selection source on this route. If there is no supported structured list, offer Default, verified locally available choices, a custom alias/full ID, and Open Claude model picker. Native aliases such as <code>sonnet</code>, <code>opus</code>, <code>haiku</code> and <code>fable</code> are examples from the official reference, not a fixed catalog or entitlement claim. Honor the current provider/account and managed restrictions. [Claude model selection](https://code.claude.com/docs/en/model-config) |
| Claude invocation and state | Pass <code>--model &lt;alias-or-id&gt;</code> and <code>--effort &lt;level&gt;</code> only on explicit overrides, or use an authorized SDK setter where documented. Installed global help lists <code>low</code>, <code>medium</code>, <code>high</code>, <code>xhigh</code>, and <code>max</code>. Intersect with the selected model's levels. Show Fast mode only when the structured session confirms availability and a supported toggle path exists, such as native <code>/fast</code> where it applies. Display <code>assistant.message.model</code>, <code>perTurnEffort</code>/<code>effort</code> and reported speed for the actual result. [Claude CLI reference](https://code.claude.com/docs/en/cli-reference) · [Claude model configuration](https://code.claude.com/docs/en/model-config) |
| Codex app-server | Prefer <code>model/list</code> for an owned app-server connection supporting it. Use model ID, default flags and server-supported reasoning efforts. Query that profile only. Merge a local fallback with source labels when the list is unavailable. [Codex App Server model listing](https://learn.chatgpt.com/docs/app-server) |
| Codex local catalog | Read <code>$CODEX_HOME/models_cache.json</code> with a bounded, allowlisted adapter. Locally observed top-level <code>models[]</code>, <code>fetched_at</code>, <code>client_version</code>, <code>etag</code>, and <code>identity</code>. The cache had 12 entries, 10 marked <code>visibility: list</code>. Model fields include <code>slug</code>, <code>display_name</code>, <code>visibility</code>, <code>priority</code>, <code>supported_in_api</code>, <code>default_reasoning_level</code>, and <code>supported_reasoning_levels[].effort</code>/<code>description</code>. Project only useful labels and capabilities. Drop identity, instructions and internal metadata. Label stale cache results and exclude hidden rows by default. Availability may change by auth mode and plan. |
| Codex configured choices | Allowlist <code>model</code>, <code>model_reasoning_effort</code>, and relevant documented model defaults from <code>$CODEX_HOME/config.toml</code> and <code>&lt;name&gt;.config.toml</code> profile layers where supported. The local config contained root model/effort settings and no matching profile layers. Show configured/custom IDs as configured rather than verified account availability. Respect managed config and expose profile names or defaults the user chose. Do not fetch arbitrary catalog paths from config. [Codex configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference) |
| Codex invocation and state | Use <code>-m &lt;MODEL&gt;</code> and <code>-c 'model_reasoning_effort="&lt;EFFORT&gt;"'</code> for explicit overrides, with <code>--profile</code> if selected. The observed cache had <code>low</code>, <code>medium</code>, <code>high</code>, <code>xhigh</code>, <code>max</code>, and <code>ultra</code> across different entries. Show only the selected entry's supported levels when known. Display actual <code>turn_context.model</code>/<code>effort</code> or <code>thread_settings</code> fields. [Codex CLI reference](https://learn.chatgpt.com/docs/cli/reference) |

Cache catalog entries in memory by adapter, binary version, saved config-home profile and verified account generation. Switch the picker to the destination profile's catalog immediately and refresh when its coverage is stale. A Codex <code>--profile</code> layer can affect model configuration within its saved home. Refresh on explicit action, sign-in change or session capability update. Mark inferred/observed entries and show unavailable fields without guessing. For unverified custom choices, pass safe typed arguments to the provider and recover the draft if it rejects them. Do not update official provider preferences when the user only changes an Agent Lens default.

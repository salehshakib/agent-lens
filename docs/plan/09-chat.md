# 9. M2 Chat

[← 8](08-ui.md) · [Plan index](README.md) · [10 →](10-codex-controls.md)

The second milestone replaces the user's daily Claude Code VS Code panel workflow. Chat is a first-class capability in the shared session panel. A user can choose an available agent, saved profile, and project, start a conversation, or open a session from the sidebar and continue its history. The same panel shows streamed replies, provider-visible thinking, tool activity, files, and child runs. Account, model and usage information stays in view while the user works. Each user authenticates through the installed official CLI for the selected provider.

## Composer and session flow

1. **Start or continue.** New chat chooses a local project, adapter, profile and supported model/effort settings. Continue resolves the sidebar row to the exact Claude session ID, owning profile and recorded workspace. Support every compatible local main session the sidebar shows, whether it originated in Agent Lens, Claude's panel or a terminal. For a missing repo, different account profile or concurrently active owner, show the specific condition and preserve the draft. Select the correct subtree/profile before resuming. Never guess a session from its title or automatically fork it.
2. **Send.** Keep an editor-sized multiline draft with Send or Queue, Run in background, model and effort, optional Fast or permission mode, and attachment chips. Display adapter-supplied effective values next to the picker. A pending bubble has a local message ID. Turn it into the canonical prompt on a valid stream acknowledgment or unique transcript match. Preserve a failed or unsent draft. An unconfirmed send after host restart requires a check or explicit retry rather than resubmission.
3. **Stream.** Turn provider text blocks and partial deltas into progressive rows with stable IDs. Group visible thinking and approved progress separately from the final response, and discard signatures and encrypted/internal payloads. Use tool call/result, subagent identity, and task progress for live lane updates. Follow the same safe output limits and scroll behavior as the history timeline. Map stdout and transcript copies into the same row; keep append-only observation available if streaming reconnects late.
4. **Queue.** Allow the user to add, edit, or remove one or more drafts while a turn runs. The default local queue is FIFO and sends the next message only at a confirmed eligible turn boundary. Live steering is an independent action where a provider exposes and verifies it. Show the applied model and attachment set for each queued draft. Pause automatic delivery after an interrupt, error, account switch, unavailable attachment, or unknown acknowledgment. Keep unsent contents in memory by default.
5. **Approve or deny.** Render a distinct inline request with provider tool identity, bounded sanitized arguments or diff, affected files, and the actual available decision labels. Keep an immutable proposal ID and binding to tool call, current turn, owner, and expiration. Send each decision once through the provider's supported channel. Preserve allow/deny rules and auto-mode behavior. Persist an authorization rule only when the provider offers that option and the user chooses it. Treat a user-input request or plan approval as its own supported interaction. For tool prompts covered by no safe transport, keep the provider's denial or hand off to the official terminal with a clear state.
6. **Run in background.** Attach the background flag to the pending turn or task before launch and reconcile it to the canonical work ID on acknowledgment. Keep the prompt, deltas, tool calls, and results in its background transcript and status surfaces while Show in main chat is off. Keep permission and input requests bound to the owned channel. Notify and open the relevant request from Background tasks when it needs attention. Keep one writer and ordinary queue ordering per session. Use a provider-supported background task or an explicitly chosen separate child/fresh session for concurrent work. An active turn keeps the same owner when its display changes. See [§8](08-ui.md) for the visibility controls.
7. **Interrupt and stop.** Offer Interrupt turn and targeted Stop agent with separate labels. Interrupt cancels the active turn through a verified provider route and keeps the conversation usable when supported. For root Stop, end only the verified owned worker or exact eligible background session and await terminal evidence. Pause its pending queue and preserve the actual outcome if completion wins a race. See the per-target routes below.

## Context, attachments, commands, and settings parity

- **Files, selection, screenshots.** Expose Attach files, Attach selection with path/range, and an explicit image-paste or screenshot-file action. Resolve paths through the host and separate a file reference from content the user explicitly includes. Validate size, MIME, repo permissions, sensitive paths and adapter limits. Send typed image or document blocks only where supported. A host-side safe file reference gives the provider its normal opportunity to read the file under its own permissions. Show exactly what has been attached and let the user remove it before sending.
- **@-mentions.** Offer a keyboard-accessible workspace path picker with safe scope and search. Insert provider-native file mentions when the transport implements them. Otherwise insert a labeled, validated local reference or ask explicitly before including a selected excerpt. Do not auto-attach the repository.
- **Slash commands and skills.** Populate commands, descriptions, arguments, and available skills from the supported session surface, such as CLI init data when exposed or SDK <code>supportedCommands()</code>. Resolve entries against current project settings and permissions. Preserve native slash semantics, including model, effort, and fast-mode controls where exposed, and provide the official terminal for commands whose interactive UI is unavailable. A terminal handoff for a feature essential to the user's daily workflow stays an open parity gap until addressed. [Claude commands](https://code.claude.com/docs/en/commands) · [Agent SDK session methods](https://code.claude.com/docs/en/agent-sdk/typescript)
- **Configuration and trust.** Run Claude Code in the recorded cwd using the chosen installed binary and profile, with native settings precedence and global/project <code>CLAUDE.md</code>, auto-memory, skills, plugins, hooks, MCP servers, user/project/local <code>settings.json</code>, and managed policy. Use the configured permission and auto modes. Avoid startup flags that replace these settings or suppress customizations, including <code>--bare</code>, <code>--safe-mode</code>, or <code>--strict-mcp-config</code>. Non-interactive CLI skips its trust dialog, so enforce VS Code Workspace Trust and local path eligibility before spawning. Verify whether CLI print inherits all required settings or needs <code>--setting-sources user,project,local</code>. The SDK route explicitly loads the corresponding sources. Run parity checks for executable hooks and MCP before enabling normal work. [Claude settings precedence](https://code.claude.com/docs/en/settings) · [Claude programmatic mode](https://code.claude.com/docs/en/headless)
- **Context and usage.** Beside the composer show context fill/current capacity, model and effort, and recorded turn/session usage with a link to Usage. Prefer a supported structured context surface, such as SDK <code>getContextUsage()</code> or the installed status-line relay. Otherwise show known last-request data. Record cached/reasoning categories without double counting. When settings or a fallback changed the model, differentiate requested from effective. [Agent SDK context usage](https://code.claude.com/docs/en/agent-sdk/typescript)

## Targeted Claude Stop

| Target | Supported evidence and button behavior |
| --- | --- |
| Background subagent or Bash task in an Agent Lens-owned stream | The public Agent SDK <code>Query.stopTask(taskId)</code> targets one running background task. Bind the live task ID and spawning tool call to the selected lane and owned streaming connection. Use the live run identity when a task can restart under the same ID. <code>task_started</code>, progress/update, and terminal task notifications can establish the binding and outcome. Test the supported native bridge for an equivalent targeted operation first. Installed print/stream help establishes observation and supplies no targeted Stop flag. The SDK documents the capability and the direct native stream transport and installed CLI/SDK combination require a disposable runtime test. [Claude SDK query methods and task events](https://code.claude.com/docs/en/agent-sdk/typescript) |
| Foreground subagent in an Agent Lens-owned stream | Verify a supported single-child route independently. The SDK documents <code>Query.backgroundTasks(toolUseId)</code> for moving a selected running tool to the background. Test whether the exact child can be moved and then stopped by its verified task ID without affecting its parent or siblings. The in-session <code>TaskStop</code> tool documents background task scope and a transcript entry alone grants no control. When target-level control is unavailable, show the reason and offer the separate Interrupt turn action where supported. [Claude SDK query methods](https://code.claude.com/docs/en/agent-sdk/typescript#query) · [Claude subagents](https://code.claude.com/docs/en/sub-agents) |
| Owned main turn or worker | A streaming <code>Query.interrupt()</code> interrupts the query. An abort or process shutdown ends the owned query or worker. Verify the Windows transport and scope. Label it Interrupt turn or Stop session as appropriate and never use it as a fallback for a child Stop. [Claude SDK query methods](https://code.claude.com/docs/en/agent-sdk/typescript#query) |
| Native background session registered by Claude | Installed help documents <code>claude agents --json</code> and <code>claude stop &lt;id&gt;</code>. The latter stops a whole registered background session. Enable a separately labeled Stop session after verifying the exact registered ID, profile, session kind, and runtime stop behavior. An attached terminal can open or resume access through official <code>claude attach &lt;id&gt;</code>. |
| Ordinary external Claude session, including the official VS Code panel | Observe its agents, tasks, and transcripts. The installed CLI help and public SDK surface establish no way to attach to that live control stream and stop a specific subagent. Disable Stop agent with the reason and direct the user to the owning panel or terminal. Seeing a PID, agent ID, or lifecycle record grants no stop capability. |

Stop agent is an M2 deliverable. Confirm the exact profile, session, live channel, and task identity immediately before sending the request. Show Stopping until provider terminal state or matching metadata confirms the outcome. If the child ends naturally first, show its actual outcome. If the native bridge and an authorized compatible SDK-backed path cannot deliver targeted Stop, report the parity blocker before closing M2. Avoid private IPC and name-based process actions.

## Claude integration options and recommendation

Installed CLI 2.1.330 confirms streaming input/output in print mode, partial messages, acknowledgments, forwarding subagent text, explicit resume, setting sources, and host permission prompts. Anthropic documents <code>--permission-prompt-tool</code>. The flag appears in the installed binary but is omitted from its top-level help, and a help-only invocation cannot verify its runtime behavior. Test it before declaring the approval route available. The installed help exposes <code>manual</code> and <code>auto</code> as named permission modes. Inherit the user's active mode unless they explicitly change it. [Claude CLI reference](https://code.claude.com/docs/en/cli-reference)

**Selected route.** Build chat around the user's installed official CLI and saved profile. Evaluate the SDK with its own supported authentication in a disposable setup if a core permission, input or cancellation interaction needs it. Keep the native route for distribution and report any essential parity gap that remains. A native terminal or panel handoff is available for external ownership and unsupported interactions.

Future CLI probe shape, after implementation authorization. Keep stdin open for streamed input. Use the exact recorded session and cwd when adding <code>--resume "&lt;SESSION_ID&gt;"</code>. Attach the permission tool arguments only after verifying the local bridge, without disabling existing MCP servers.

~~~powershell
claude -p --input-format stream-json --output-format stream-json --verbose --include-partial-messages --forward-subagent-text --replay-user-messages --setting-sources user,project,local --permission-prompts host
claude -p --resume "<SESSION_ID>" --input-format stream-json --output-format stream-json --verbose --include-partial-messages --forward-subagent-text --replay-user-messages --setting-sources user,project,local --permission-prompts host --mcp-config "<APPROVAL_BRIDGE_CONFIG>" --permission-prompt-tool mcp__agent_lens__approve
~~~

Before taking over a live session, use a documented ownership or attachment flow. Installed <code>--bg --resume</code> may create a copy when the target already runs, so it cannot silently implement Continue. Match ownership and the exact result ID, and require a supported handoff or idle owner release. On host reload, rediscover the transcripts, reconcile acknowledgments and pending requests, and retain historical access even if the chat channel itself cannot reconnect. M2 closes only after the milestone's parity checklist passes on the target machine.

# 17. Chat runtime and Claude controls

[← 16](16-slash-commands.md) · [Plan index](README.md) · [M2 implementation →](m2-implementation.md)

The extension host owns chat connections, drafts and queues, provider control requests, and reconciliation with local history. The webview receives a sanitized conversation model and sends typed requests scoped to the current conversation. The [chat design](09-chat.md) describes the interaction. The [M2 implementation plan](m2-implementation.md) sequences live capability checks and delivery.

## What the CLI and SDK expose

- The installed Claude Code 2.1.330 reports streaming input and output, partial messages, replayed user messages for acknowledgment, forwarded subagent text, explicit resume, settings sources, and host permission prompts in help. Its help refers to `--permission-prompt-tool` inside the description of `--permission-prompts`. Anthropic documents both options and the prompt tool’s limitations. Help and documentation establish candidate interfaces. Launch, permission enforcement, and control behavior still require Phase A verification in the target host. [CLI reference](https://code.claude.com/docs/en/cli-reference) · [Programmatic mode](https://code.claude.com/docs/en/headless)
- The codebase already normalizes historical provider records into a shared event model. Separate limits work observed the Claude `rate_limit_event` shape and has a pending decoder in `src/host/limits/claude-probe.ts`. The open chat stream feeds the limits projection for its bound profile and can share pure decoding logic when available. Each window can arrive independently. [Adapter event model](../../src/host/adapters/types.ts)
- Anthropic documents a native interrupt control request and capability bits for the receipt and queue cancellation. The TypeScript SDK documents streaming `Query.interrupt()`, `Query.stopTask(taskId)`, and `Query.backgroundTasks(toolUseId)`. Verify that the selected CLI or CLI/SDK pair and Windows launch method actually provide the required boundaries. [SDK control methods and interrupt receipt](https://code.claude.com/docs/en/agent-sdk/typescript#query)

## Phase A permission and control verification

Verify an end-to-end approval route **before building the live chat**. Use a disposable workspace and tester-owned CLI profile, a benign capability with a clear observable effect, and permission rules that require an explicit decision. Start with the documented local MCP prompt tool using `--permission-prompt-tool` and `--permission-prompts host`. Load the trusted bridge alongside the profile’s existing MCP settings. Use a minimal verification harness first. The chat approval UI follows once the route is proven. [CLI permission flags](https://code.claude.com/docs/en/cli-reference) · [Claude permission rules](https://code.claude.com/docs/en/permissions)

1. Verify that the installed worker registers the intended bridge and actually routes a provider permission request to it. Prove allow-once and deny using effects in the disposable workspace, including that a request waits before execution and a denial leaves the target untouched. Confirm that allow, deny, hooks, managed policy, and auto mode retain their native precedence. Verify effective mode at launch and when it changes.
2. Verify immutable request identity and the effect of duplicate, stale, expired, mismatched, or disconnected responses. Check bridge startup failures, worker exit, connection loss during approval, timeout, and reload. Record which tool classes can prompt, what the provider acknowledges, and how the CLI behaves when the bridge is unavailable. The CLI prompt tool cannot approve MCP tools marked as requiring user interaction. Check questions, plan approval, and other interactive requests individually for documented support and actual behavior. [CLI prompt-tool restrictions](https://code.claude.com/docs/en/cli-reference) · [SDK approvals and input](https://code.claude.com/docs/en/agent-sdk/user-input)
3. Verify stream framing, turn completion, user replay acknowledgment, persistence and exact resume, ownership, profile isolation, status and task evidence, and native interrupt receipts. Run the existing milestone’s settings and tool parity checks on Windows before enabling work in a normal workspace. Record supported versions, effective settings, observed transcripts, and the verified scope of each capability. [Milestone verification](15-milestones.md)

**Fail closed.** Until the gate passes, keep live Send and Resume disabled for the affected configuration and offer the official terminal or owning UI with a specific reason. A missing bridge, unverified decision route, or unsupported permission mode keeps the corresponding control disabled. If a bridge fails mid-turn, invalidate its requests, pause sending, apply provider denial where possible, and end the verified owned worker if needed to prevent an unresolved request from proceeding. Surface the known outcome or an unknown state pending verification. Use the same fail-closed behavior on version or configuration changes that invalidate the evidence.

In the later approval UI, bind actions to an immutable proposal ID, exact channel, current turn, tool call, proposal revision, and expiry. Allow one decision and apply persistent permission updates only when the provider offers them and the user explicitly selects them. A tool observation or saved transcript can display past decisions. A current, verified provider request is required to answer. Sanitize the visible proposal, retain only necessary data in host memory, and withhold Allow if the UI cannot represent the consequential action. [Security and projection](14-security.md)

## Native launch and configuration

Use the unmodified official CLI with the user’s chosen profile, the recorded cwd, and VS Code Workspace Trust and local path eligibility established before spawn. Verify effective profile, regular user/project/local settings, managed policy, `CLAUDE.md`, auto-memory, skills, plugins, hooks, MCP servers, permission rules, and overrides. Programmatic mode skips the interactive trust dialog. Check which settings print mode inherits and whether `--setting-sources user,project,local` is needed. Keep normal chat free of the quota probe’s isolation flags such as `--strict-mcp-config` and other settings overrides such as `--bare` or `--safe-mode`. Verify configured shell behavior, including Git Bash on Windows where applicable. [Claude settings and trust](https://code.claude.com/docs/en/settings) · [Programmatic mode](https://code.claude.com/docs/en/headless) · [Profile verification](12-accounts.md)

Resolve the user-configured or installed native executable and the selected profile’s environment. The Windows npm shim points to `claude.exe`. Spawn it directly with an argument array, hidden, with UTF-8 pipes and stdout and stderr handled separately. Keep stdin open for streamed messages and host controls. Verify bounded framing, process cleanup, initialization failure, and paths with spaces. Authentication stays within the official CLI and its sign-in flow. [Release checks](15-milestones.md)

This command shape describes a future Phase A run using the disposable setup and its approval bridge. Use the approved repo cwd and bound profile environment. For a continuation check add `--resume "<SESSION_ID>"` with the exact recorded ID.

~~~powershell
claude -p --input-format stream-json --output-format stream-json --verbose --include-partial-messages --forward-subagent-text --replay-user-messages --setting-sources user,project,local --permission-prompts host --mcp-config "<APPROVAL_BRIDGE_CONFIG>" --permission-prompt-tool mcp__agent_lens__approve
~~~

## Ownership and resume

- A new tab has a local draft ID until the adapter binds it to a confirmed provider session. An existing identity includes adapter, owning profile, exact native session ID, and recorded workspace. Refresh writer and owner evidence immediately before launching or resuming. Maintain one writer per conversation, including when a run is hidden or its tab is closed. Recoverable missing workspace, account, or competing owner states retain chat history and the draft. [Session identity](04-session-model.md) · [Accounts](12-accounts.md)
- Continue only after an idle owner releases the session or a documented handoff is verified. Send `--resume` with the exact recorded ID and confirm that the stream and persisted history report the same session. Treat an unexpected ID as a launch failure for Continue and stop further sends on that channel. `--bg` may start a copy, so Continue uses the explicit ownership flow. CLI attach is a separate official terminal action for an eligible registered background session. [Claude background sessions](https://code.claude.com/docs/en/agent-view)
- Honor native permission settings and explicit user choices. Claude documents different permission-mode restoration rules for interactive and print-mode resume. Verify the effective resumed mode before sending and show it in chat. A required mode that the transport cannot verify or preserve leaves Send unavailable with its reason. [Claude permission mode on resume](https://code.claude.com/docs/en/sessions#permission-mode-on-resume)
- Each send has a local message ID and a provider acknowledgment where available. Canonicalize it from that acknowledgment or an unambiguous transcript match. Keep locally queued drafts editable and in memory by default. Dispatch only when the previous turn is confirmed eligible and revalidate its attachments and requested options. If the stream or host fails around submission, reconcile before offering an explicit retry. Automatic sends pause while delivery is ambiguous.
- Interrupt sends one request on the verified channel for the exact turn, pauses the local queue, and uses receipts and turn evidence to reconcile messages Claude may already have accepted. Preserve the actual outcome when completion wins the race. Surface **Interrupting** until host evidence resolves it. Keep the conversation available on the same worker if supported, or reopen by exact resume after the owner releases it. An explicit **Stop session** may end the whole owned worker. A child stop always uses its own verified target and route. [Interrupt receipt](https://code.claude.com/docs/en/agent-sdk/typescript#sdkcontrolinterruptresponse)
- Background visibility is independent of execution ownership. For concurrent work, use a verified provider background task or an explicitly selected separate child or fresh session. On reload, rediscover persisted history, reconcile acknowledgments and pending requests, and restore observation even when the original control channel is unavailable. Invalidate stale permissions and leave ambiguous sends paused. [Background task visibility](08-ui.md#background-tasks)

## Shared events and provider adapters

Extend the existing host adapter contract for verified capabilities such as live send, resume, interrupt, commands, approval, and child Stop. Each official CLI adapter owns its launch, input and output framing, native command mapping, and supported controls. Parse stdout as bounded newline-delimited JSON and keep raw provider records and stderr in the host’s content boundary. Only a sanitized projection reaches the webview. [Host architecture](07-architecture.md) · [Security and privacy](14-security.md)

| Stream evidence | Shared update |
| --- | --- |
| Initialized session and user replay | Confirm session identity and effective settings where supplied. A matching replay can acknowledge a pending prompt. Provider commands report completion or failure on their own cards. |
| Assistant block start, delta, and completion | Update a provisional row using stable lane, response, and block identity. Confirm full text against the complete block or final message without duplicating it. Forward supported, visible summaries only. |
| Tool calls, results, and recognized task lists | Pair calls and results by lane and call ID. Project permitted file evidence, including recorded diffs. Recognize todo tools such as `TodoWrite` where the adapter verifies their schema. Other tool calls use the generic card. |
| Subagent and background task records | Bind task and child lane to the originating call and exact run identity. Reuse verified transcript and launcher evidence to place a linked Codex run at its spawning row. |
| Turn result, usage, context, and limits | Apply the confirmed turn outcome and usage once. Merge independent, profile-scoped windows into the limits store. Unknown or unavailable evidence stays visible as such. |
| Live permission or input request | Validate the request against its owning provider channel and project the allowable decisions as an inline card. Resolve through that same channel. |

Reconcile stdout and watched transcript records using provider identities, response and call IDs, and the existing precedence for corroborated evidence. Prefer explicit identity across sources and keep unresolved observations pending. Control actions depend on the live channel and verified capabilities. [Claude record evidence](02-claude-code-data.md) · [Unified session model](04-session-model.md)

## Targeted Claude Stop

| Target | Route and evidence |
| --- | --- |
| Background subagent or Bash task in an Agent Lens-owned stream | Verify that the native bridge or compatible SDK `Query.stopTask(taskId)` targets a single running task. Bind the live task ID, spawning tool call, and run identity to the owned channel. `task_started`, task progress, and terminal notifications can establish the binding and outcome. The installed print help documents observation but no targeted Stop flag. [SDK task events and controls](https://code.claude.com/docs/en/agent-sdk/typescript#query) |
| Foreground subagent in an Agent Lens-owned stream | Verify a supported single-child route independently. The SDK documents moving a specific foreground tool with `Query.backgroundTasks(toolUseId)`. Verify that moving and stopping the resulting task leaves the parent and sibling running. `TaskStop` concerns background tasks. Where exact child control is unavailable, explain it and offer the separate **Interrupt turn** action where supported. [SDK task controls](https://code.claude.com/docs/en/agent-sdk/typescript#query) · [Claude subagents](https://code.claude.com/docs/en/sub-agents) |
| Owned main turn or worker | Use the verified native interrupt or SDK `Query.interrupt()` to interrupt the turn. Abort or shut down the exact owned worker for **Stop session**. Verify Windows scope and cleanup. |
| Native registered background session | Installed help documents `claude agents --json`, `claude stop <id>`, and `claude attach <id>`. Enable **Stop session** only after verifying the registered background kind, exact ID, owning profile, and runtime behavior. The official terminal attach action opens the eligible background session. |
| Ordinary external Claude session, including the official VS Code panel | Observe its agents, tasks, and transcripts. Current CLI help and the SDK establish no verified child stop route for someone else’s live channel. Disable **Stop agent**, explain who owns it, and link to the official panel or terminal. |

Stop agent is an M2 deliverable. Revalidate profile, session, live channel, and target immediately before sending. Show **Stopping** until terminal evidence or matching metadata confirms the state. If the target ends naturally first, show its actual outcome. Grant control only to routes demonstrated for that specific target. Avoid private IPC and process-name matching. Record a targeted Stop blocker if both the native bridge and an authorized compatible SDK path fail to meet the requirement. [M2 completion criteria](15-milestones.md)

| Area | Installed official Claude Code CLI | Official Claude Agent SDK for TypeScript |

| History | Verify persistence under the intended cwd and home, exact resume ID, and writer behavior against new and historical sessions. | Configure persistent sessions and the intended cwd and home. Verify reuse of the CLI session ID, main history, and child transcript files. [Claude session storage](https://platform.claude.com/cookbook/claude-agent-sdk-05-building-a-session-browser) |

Use the installed CLI for the distributed chat route. Evaluate the SDK in an authorized disposable setup if a permission, input, or cancellation capability needs it. Report any remaining essential parity gap before closing M2, including work handed off to the official terminal.

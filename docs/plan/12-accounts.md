# 12. Accounts

[← 11](11-models.md) · [Plan index](README.md) · [13 →](13-tech-stack.md)

Accounts is a shared per-adapter view with several saved profiles side by side. M1 shows profile-scoped discovery and read-only status from verified probes. M2 adds Claude sign-in and sign-out and M3 adds Codex actions. Each profile has a user-chosen name and unique canonical config home. Show the active profile for each adapter and an instant **Switch profile** action. Show **Signed in**, **Signed out**, **External configuration**, or **Unknown**, the last check, and subscription/Console/API or another mode if the official probe reports it. Before enabling chat and runs, confirm the user has authenticated their selected profile through the official CLI. History browsing can remain available independently. Render plan and email only if supplied by that official status surface. Keep these values in memory and out of logs, toasts, exported usage and timeline entries.

- Probe on Accounts open or explicit refresh and after an auth operation, with bounded output/time, exact CLI/profile, no prompt, and no token refresh request. Validate result shape and expected exit semantics. Read-only investigation checked help only. It did not collect identity, plan, or status output. Treat unsupported formats, stale status, network-only results, missing binary, env/provider conflicts, or probe errors as Unknown. Offer Open official account status in terminal if needed.
- Sign in and Sign out run only after a user action, via a VS Code terminal or an official client-driven browser flow. The user completes authentication with the provider. Protect CLI device codes and prompts from transcript capture. Keep keys and OAuth data out of webviews and process arguments. Agent Lens excludes credential files such as <code>~/.codex/auth.json</code>, Claude credential stores and keyrings from all reads and writes. The status path emits only allowlisted account metadata.
- **Save and switch.** Save only the profile ID, label, provider, approved canonical home and local preferences. Reject duplicate or overlapping homes and reparse aliases. Pass the home override in each subprocess's environment, including official terminal login/logout actions, without a global environment change. Switch the selected profile immediately for new launches, model choices, and active gauges. Switching uses the target's existing CLI sign-in. In-flight channels and drafts stay bound to their original profile, and delivery for affected queues pauses until the user returns or resumes explicitly. Exact resume always uses the session's recorded home and eligible account context. Codex <code>--profile</code> config overlays are independent of saved account homes.
- **Scope sessions and usage.** Browse historical sessions under their source home even while another profile is active. Filter sessions and token/context summaries by profile. Keep historical tokens attributed to their original home and observed time, including across a re-login. A marked cross-provider edge preserves each session's own profile. Unknown home/account provenance stays unassigned. Never infer account ownership from the username, transcript IDs, or selected profile alone.
- **Scope limits and account transitions.** Bind Claude relay/refresh and Codex limit observations to the producing profile and current verified account generation. Keep quota windows, reset times, alerts, and model catalogs within that scope. Invalidate them on sign-in/out or detected account change and wait for fresh matching samples. Exclude older rollouts and late writes by prior-account owners after a change. When producer/account scope is ambiguous, show Unavailable. A switch between verified homes uses the destination's own valid data and never borrows samples across homes.
- **Verify before enabling.** On Windows use two disposable homes per adapter with distinct tester-owned sign-ins. Verify canonical root and private permissions, effective CLI home, auth mode and store isolation, independent login/status/logout, settings/model/catalog scope, transcript and resume paths, child processes and CLI terminals, and quota isolation across switches and re-login. Check ambient auth and state overrides, including shared account/keyring modes and alternate runtime or SQLite homes. Verify that a sign-out of one profile leaves the other signed in using only official status interfaces. Block isolation-dependent launch, resume, sign-out and gauges for affected scopes when the CLI shares state or cannot establish the effective identity. Keep eligible local history available.

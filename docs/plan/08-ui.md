## Conversation screen

Open Agent Lens into chat. An empty conversation has a focused composer, the current project and profile, and a `/resume` entry point. A resumed conversation opens its history in order above the input. Each editor tab represents one conversation. New chat and `/clear` open a fresh conversation in a separate tab. Selecting a different session from `/resume` or the sidebar opens or reveals its tab. Read-only conversations keep their history and inspection controls and explain how to continue when a route exists.

Keep the header to the conversation title, project, adapter, profile, ownership state and a **Views** control. Chat stays selected while a slash-command card opens below the command. **Views** opens the existing Timeline, Agent map, Files, Usage and Background tasks tabs for the same session. Returning to Chat restores its draft, scroll anchor, and focused control when available. Global Usage and Background tasks stay reachable from the sidebar and the VS Code Command Palette. The timestamped Timeline preserves actor and lane filters for evidence inspection. [Chat behavior](09-chat.md) · [Slash-command catalog](16-slash-commands.md)

## Transcript rows and cards

- Show user messages and assistant replies in conversation order. A tool gets a short, folded row with its tool name, safe target and outcome. Its bounded result expands directly underneath. Preserve output line breaks and distinguish partial, truncated, and unavailable output. Show provider-visible thinking separately in a folded disclosure. Render Edit and Write with an embedded diff when one was recorded. Keep a path and evidence action when patch data is unavailable.
- Put the reported todo list next to the turn that updated it, with text and state for each item. Subagents and linked Codex runs sit in folded blocks at their verified spawning action, with status, elapsed time, and an Open transcript action where available. Use the detailed Timeline for lane-level inspection. Unresolved launches retain their observed location and label until evidence establishes a parent.
- Give each inline card its command label and scope. Reuse the same Agent map, Files, recorded diff, Usage and Background tasks behavior as the secondary views. Show an explicit empty, loading, stale, unavailable, or redacted state as appropriate. Keep account-wide actions and exact-agent Stop scoped to the subject shown in the card. [Slash-command catalog](16-slash-commands.md)
- Auto-follow while the user is near the bottom. Preserve their place when they scroll away and show **Jump to latest** with a new-event count. Keep expanded state and stable focus as rows receive deltas. Announce turn, approval, and completion transitions through a live region at a readable cadence. Apply the same masking and private display projection to both the conversation and the detail views. [Security and privacy](14-security.md)

## Composer, slash menu, and status

Place the multiline composer beneath the transcript with **Attach**, **Commands**, and **Send** or **Queue**. Show removable attachment chips above the text field. A pending approval offers its own Allow and Deny controls with the current target and proposed action. Keep the command and file menus close to the caret. A narrow panel can dock the popup above the composer. Display current effective model, effort, context fill and the two profile-scoped limit windows in a text status line below the input. The active permission mode and queued count use the remaining space or wrap onto a second line. Offer reset times and sample freshness through the Usage card and accessible detail. Use **Unknown** or a specific unavailable state when the evidence is missing. [Composer and keyboard behavior](09-chat.md) · [Usage and limits](06-usage-and-limits.md)

Type `/` as the first non-whitespace character in the composer to show available commands with descriptions. Arrow keys change the highlighted choice, Enter accepts the highlighted completion, and Escape dismisses the menu and leaves the draft in place. A command with arguments can offer a second list of choices before execution. The slash menu and the visible Commands button lead to the same list. Keep native skills labeled with their source and show a reason for unavailable entries. [Slash-command catalog](16-slash-commands.md)

~~~text
+---------------------------------------------------------+
| /                                                       |
| > /resume    Find or open a conversation                |
|   /usage     Inspect tokens and limit windows           |
|   /context   Inspect current context fill               |
|   /agents    Inspect the agent tree and Stop controls   |
|   /files     Inspect files touched in this conversation |
|   /compact   Compact conversation context  [Native]     |
+---------------------------------------------------------+
~~~

~~~text
Opus / high / Context 26% / 5h 62% / 7d 39%
Opus / effort unknown / Context unknown / 5h 62% (stale) / 7d unavailable
~~~

Use VS Code theme variables for surfaces, diff lines, fonts and focus. Keep the layout usable at narrow editor widths, with visible labels and focus in light, dark and both high-contrast themes. Respect reduced motion. The conversation uses Agent Lens styling and VS Code conventions. [VS Code webview theming](https://code.visualstudio.com/api/extension-guides/webview#theming-webview-content)

## Activity bar and sidebar

Keep the Agent Lens Activity Bar entry, compact Usage glance and **All projects** session tree as secondary navigation. The `/resume` picker uses the same catalog, defaults to the current project and includes an **All projects** option across approved homes. Preserve repo search, adapter and profile filters, and Usage, Accounts, and Background tasks actions in the sidebar. Group tree entries by project, then Live, Today and Earlier in local time. Sort by latest relevant activity and keep an accessible Load older action. Place verified children under their spawning session or agent and show the child repo for cross-project links. Keep selections and filters across reopen. Show New chat, Continue, Start, Follow up and Stop according to the adapter and session capabilities.

## Session detail views

The secondary **Views** tabs keep the M1 session header with the title, owning profile, project/worktree, outcome, effective model or model mix, effort when available, elapsed time and scoped usage. Agent selectors can show All lanes, main only or a selected subtree. Preserve an independent scroll anchor per view. Keep a visible **Back to chat** action and show detail-tab navigation when these views are open.

- Timeline uses a restrained timestamp rail, actor and event labels, compact groupings, and readable body text. Show full recorded prompts, replies, command output, and diffs by default after masking secrets and applying the content rules in [§14](14-security.md). Prompt, commentary, inter-agent messages, and Final are visually distinct. Assistant text and final replies remain readable without expansion. Reasoning summaries and tool calls default to collapsed. A lane shows the most recent trustworthy action. Event cards preserve chronology even when multiple agents run in parallel.
- A command row shows status, duration, and command before expansion. The body preserves line breaks, supports wrap and horizontal scroll, and labels truncated or partially recorded output. Strip terminal control sequences. Keep stderr identifiable where recorded.
- Files groups activity by path and provider/agent, with quick filters for Read, Changed, and Mentioned. A sample row reads <code>src/export.ts · Read ×2 · Edited ×1 · Reviewer / Codex · [Open] [Diff]</code>. A path-only row labels the missing patch and keeps its jump-to-event action.
- The Agent map shows parent/child relationships, status and usage. Each agent has its own transcript action. Missing parent or missing child transcript is a visible state.
- Auto-follow only when the user is already near the bottom. When they scroll away, preserve their place and show a Jump to latest control with a new-event count. Support keyboard navigation and restore focus after expanding or switching views. Announce status transitions in an accessible live region, without announcing every streamed row.
- Theme through <code>--vscode-*</code> variables for editor/sidebar background, foreground, focus, borders, fonts, and diff colors. Test light, dark, and both high-contrast themes plus reduced motion. Use native icon and focus conventions, compact spacing at narrow widths, and text labels alongside status colors. No remote fonts or images. [VS Code webview theming](https://code.visualstudio.com/api/extension-guides/webview#theming-webview-content) · [Theme color reference](https://code.visualstudio.com/api/references/theme-color)
- Status bar shows the local live count and compact provider quota indicators with percent text and accessible tooltips. Use separate provider items or a compact combined item that opens global Usage. Show clear states for missing sources, waiting for a quota refresh, unavailable controls, missing patches, and scanning older history.

Render a card for the main session, every observed subagent, and each verified linked Codex run under its launching lane. Include Codex children using their verified parent edges. Parent-to-child connector lines show the relationships. An unresolved agent remains labeled until evidence arrives. Each card shows a status dot and text (Running, Done, Failed, or Stopped when confirmed), name or description, effective model, elapsed time, and token count. ## Run signals

Run signals appear wherever the affected lane or turn appears. In Chat, a loop label attaches to the affected folded tool or run block. A check outcome appears near the end of the turn, and context pressure appears with the status line's context value. Use VS Code warning colors with a text label and accessible description. Each signal links to its evidence rows and uses the control eligibility already in effect. [Run signal definitions](04-session-model.md#run-signals)

| Signal | Timeline | Agent map card and popover | Sidebar row | Session header |
| --- | --- | --- | --- | --- |
| Possible loop | The repeated rows group into one collapsible row such as <code>Read src/export.ts · repeated 4×</code> with a warning label. Expanding it shows each call and result. | A live streak shows <code>! Possible loop · Read ×4</code> on the card. The popover lists the repeated call with its count. Stop agent stays available when the existing Stop rules allow it. | Live streaks only, as a short warning label next to the status. | Count of live streaks in this session. |
| Done without checks | A marker row at the end of the turn: <code>No checks after edits · 3 files changed</code>, <code>Last check failed · npm run check · exit 1</code> or <code>Check result unknown</code>. It links to the last edit and the last check. | Shown on the root card of the turn. | Shown on the session row until a later turn in the same session passes a check. | The latest turn's outcome. |
| Context level | Not a row. | High or Critical next to the context figure on cards that have a percentage. | High or Critical next to the session status. | Gauge color and label (see [§6](06-usage-and-limits.md#context-fill-levels)). |

~~~text
+--------------------------------------------------------------------------------+
| dashboard / Fix export flow                 Claude · Done 06:41 · Context High |
| Main + 1 Claude agent · 1 delegated Codex worker            [Session usage]    |
|--------------------------------------------------------------------------------|
| 10:44:02    > Reviewer   ! Read src/export.ts · repeated 4×     Possible loop   |
| 10:46:51  Codex          File change src/export.ts                     +8 / -2 |
| 10:47:30  Claude main    Final  The export now downloads as a file.            |
| 10:47:30  ! No checks after edits · 1 file changed   [Last edit] [Turn files]   |
+--------------------------------------------------------------------------------+
~~~

Timeline filters gain a **Signals** option that shows only rows with a signal, and the sidebar filter gains **Has warnings**. The signal settings (loop threshold, check patterns, ignore globs, context thresholds) live in one Agent Lens settings group with a link from each signal's tooltip.

## Parent navigation

Every subagent, child thread and linked Codex run has an **Open parent** action in its transcript block or detail, the session header breadcrumb, the Agent map popover and the sidebar row action. It is also available as the `agentLens.openParent` command, with no default keybinding so it doesn't clash with existing shortcuts.

- **Target.** It opens the parent session at the exact spawning row from [§4](04-session-model.md#run-signals): the Agent call for a Claude subagent, the spawn record for a Codex child thread, or the Bash card for a linked Codex run. The target row is scrolled into view, briefly highlighted and focused. The highlight respects reduced motion.
- **Several launches.** A resumed Codex thread with several verified launch edges opens a small menu that lists each launch with its Claude session, lane and time, newest first.
- **Back.** Opening a parent reveals its conversation tab and focuses the spawning block or the selected detail view's evidence row. Keep the origin tab, view, lane filter and anchor so **Back** can restore the exact position.
- **Unavailable.** A root session hides the action. An unresolved parent keeps the action visible and disabled, with a reason such as "Parent session not found yet" or "Launch not verified". A parent from a missing or disabled source explains that state.
- **Breadcrumb.** The session header shows the chain from the root, for example <code>dashboard / Fix export flow › Claude main › Bash › Codex validator</code>. Each segment opens that ancestor.

## Run statistics (Later)

A **Stats** tab next to Usage is scheduled after M3. It uses the same Day, Project, Session and profile filters and the adapter selector. It uses local observations and works offline. [Run statistics milestone](15-milestones.md#later--run-statistics)

| Metric | Definition |
| --- | --- |
| Tool calls | Paired tool calls by tool, agent, provider and model. |
| Tool failure rate | Tool results with a recorded error or failed state, divided by paired results with a known outcome. Unknown outcomes are shown separately and not counted as success. |
| Command failure rate | Shell or exec calls with a recorded nonzero exit, divided by those with a recorded exit. Check commands are also shown on their own. |
| Loops | Count of Possible loop streaks, longest streak, and the tools that loop most. |
| Done without checks | Turns that ended with No checks after edits or Last check failed, as a count and as a share of completed turns that made edits. |
| Context pressure | Sessions that reached High or Critical, and compactions observed after a crossing. |
| Stops and interruptions | Confirmed Stop, interrupted and failed turns by agent and provider. |

## Background tasks

The Agent map, sidebar, `/tasks background` card and **Background tasks** view show background entries with the parent session, provider/profile, status and an Open action. Each confirmed completion gets one notification with an Open action. The composer and run form offer **Run in background** for eligible work. Background entries start with **Show in main chat** off. The session toggle controls the default, and an item toggle overrides it. Foreground entries show by default and can also be hidden individually. Opening a background transcript preserves the main chat view. Turning visibility on reveals its existing folded run block at the original turn or spawning action and adds new events there. Turning it off hides the block while keeping the transcript, Files and Usage attribution available. Record only the visibility choices by stable IDs. Keep pending permission requests accessible from the background item and its status notification. [Chat behavior](09-chat.md)

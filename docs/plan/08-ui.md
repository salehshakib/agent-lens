## Activity bar and sidebar

Use an Agent Lens Activity Bar entry with a compact Usage glance and a session tree. Default to **All projects** across approved homes. Provide repo search/filter, adapter and profile selectors, and Usage, Accounts, and Background tasks actions. Group by project, then Live, Today, and Earlier in local time. Sort each group by latest relevant activity. Load older Earlier pages as the user scrolls, with a keyboard-accessible Load older action. Show the adapter label, compact title, outcome and accessible status text. Place children under their spawning session or agent, with an Agents subgroup when needed. A linked Codex run appears under the launching Claude task and remains searchable in the provider filter. A cross-project link shows the child repo. Persist selection and filter across reopen. Show New chat, Continue, Start, Follow up, and Stop according to the adapter and session capabilities.

## Session detail

Header shows session title, agent, owning profile, project/worktree, current outcome, effective model or model mix, effort when available, elapsed time, and scoped usage. Keep provider and agent colors secondary to labels. Timeline, Agent map, Files, and Usage share the current session. Agent selectors can show All lanes, main only, or a selected subtree. Preserve an independent scroll anchor per view. The composer and control actions join the same panel when the current adapter/session supports them.

~~~
+--------------------------------------------------------------------------------+
| dashboard / Fix export flow                            Claude · Working 02:14  |
| Main + 1 Claude agent · 1 delegated Codex worker            [Session usage]    |
| [Timeline] [Agent map 3] [Files 5] [Usage] [Background tasks]                   |
| Lane [All v]    Claude main ----- Reviewer ------ Codex validator ------------  |
|--------------------------------------------------------------------------------|
| 10:42:04  You              Fix the export flow and verify the download.         |
| 10:42:10  Claude main      I'm checking where the download response is built.   |
| 10:42:15    > Reviewer     Read src/export.ts                                  |
| 10:42:18  v Claude Bash    Codex validator shown in chat    [Open Codex run]    |
| 10:42:27      > Codex      Reasoning summary                                    |
| 10:42:34      v Codex      File change src/export.ts                    +8 / -2 |
|                         - return response.body                                 |
|                         + return response.blob()                               |
| 10:42:41      > Codex      Command npm run check                         Exit 0  |
|--------------------------------------------------------------------------------|
| [Jump to latest]                                               3 new events   |
+--------------------------------------------------------------------------------+
~~~

- Timeline uses a restrained timestamp rail, actor and event labels, compact groupings, and readable body text. Show full recorded prompts, replies, command output, and diffs by default after masking secrets and applying the content rules in [§14](14-security.md). Prompt, commentary, inter-agent messages, and Final are visually distinct. Assistant text and final replies remain readable without expansion. Reasoning summaries and tool calls default to collapsed. A lane shows the most recent trustworthy action. Event cards preserve chronology even when multiple agents run in parallel.
- A command row shows status, duration, and command before expansion. The body preserves line breaks, supports wrap and horizontal scroll, and labels truncated or partially recorded output. Strip terminal control sequences. Keep stderr identifiable where recorded.
- Files groups activity by path and provider/agent, with quick filters for Read, Changed, and Mentioned. A sample row reads <code>src/export.ts · Read ×2 · Edited ×1 · Reviewer / Codex · [Open] [Diff]</code>. A path-only row labels the missing patch and keeps its jump-to-event action.
- The Agent map shows parent/child relationships, status and usage. Each agent has its own transcript action. Missing parent or missing child transcript is a visible state.
- Auto-follow only when the user is already near the bottom. When they scroll away, preserve their place and show a Jump to latest control with a new-event count. Support keyboard navigation and restore focus after expanding or switching views. Announce status transitions in an accessible live region, without announcing every streamed row.
- Theme through <code>--vscode-*</code> variables for editor/sidebar background, foreground, focus, borders, fonts, and diff colors. Test light, dark, and both high-contrast themes plus reduced motion. Use native icon and focus conventions, compact spacing at narrow widths, and text labels alongside status colors. No remote fonts or images. [VS Code webview theming](https://code.visualstudio.com/api/extension-guides/webview#theming-webview-content) · [Theme color reference](https://code.visualstudio.com/api/references/theme-color)
- Status bar shows the local live count and compact provider quota indicators with percent text and accessible tooltips. Use separate provider items or a compact combined item that opens global Usage. Show clear states for missing sources, waiting for a quota refresh, unavailable controls, missing patches, and scanning older history.

## Agent map and agent detail

Open an **Agent map** dialog from the session or sidebar. Show the agent count and a short selection hint. Render a card for the main session, every observed subagent, and each verified linked Codex run under its launching lane. Include Codex children using their verified parent edges. Parent-to-child connector lines show the relationships. An unresolved agent remains labeled until evidence arrives. Each card shows a status dot and text (Running, Done, Failed, or Stopped when confirmed), name or description, effective model, elapsed time, and token count. Label context tokens and cumulative tokens by their actual scope. Unknown or stale evidence gets its own label.

## Run signals

Run signals from [§4](04-session-model.md#run-signals) appear wherever the affected lane or turn appears. They use VS Code warning colors, always with a text label and an accessible description, and never with motion or pulsing. Each signal links to its evidence rows. None of them adds a control beyond the ones that already exist.

| Signal | Timeline | Agent map card and popover | Sidebar row | Session header |
| --- | --- | --- | --- | --- |
| Possible loop | The repeated rows group into one collapsible row such as <code>Read src/export.ts · repeated 4×</code> with a warning label. Expanding it shows each call and result. | A live streak shows <code>! Possible loop · Read ×4</code> on the card. The popover lists the repeated call with its count. Stop agent stays available when the existing Stop rules allow it. | Live streaks only, as a short warning label next to the status. | Count of live streaks in this session. |
| Done without checks | A marker row at the end of the turn: <code>No checks after edits · 3 files changed</code>, <code>Last check failed · npm run check · exit 1</code> or <code>Check result unknown</code>. It links to the last edit and the last check. | Shown on the root card of the turn. | Shown on the session row until a later turn in the same session passes a check. | The latest turn's outcome. |
| Context level | Not a row. | High or Critical next to the context figure on cards that have a percentage. | High or Critical next to the session status. | Gauge color and label (see [§6](06-usage-and-limits.md#context-fill-levels)). |

~~~text
+--------------------------------------------------------------------------------+
| dashboard / Fix export flow                 Claude · Done 06:41 · Context High |
| Main + 1 Claude agent · 1 delegated Codex worker            [Session usage]    |
|--------------------------------------------------------------------------------|
| 10:44:02    > Reviewer   ! Read src/export.ts · repeated 4×     Possible loop   |
| 10:46:51  Codex          File change src/export.ts                     +8 / -2 |
| 10:47:30  Claude main    Final  The export now downloads as a file.            |
| 10:47:30  ! No checks after edits · 1 file changed   [Last edit] [Turn files]   |
+--------------------------------------------------------------------------------+
~~~

Timeline filters gain a **Signals** option that shows only rows with a signal, and the sidebar filter gains **Has warnings**. The signal settings (loop threshold, check patterns, ignore globs, context thresholds) live in one Agent Lens settings group with a link from each signal's tooltip.

## Parent navigation

Every subagent, child thread and linked Codex run has an **Open parent** action in the session header breadcrumb, the Agent map popover, the timeline lane header and the sidebar row context menu. It is also available as the <code>agentLens.openParent</code> command, with no default keybinding so it doesn't clash with existing shortcuts.

- **Target.** It opens the parent session at the exact spawning row from [§4](04-session-model.md#run-signals): the Agent call for a Claude subagent, the spawn record for a Codex child thread, or the Bash card for a linked Codex run. The target row is scrolled into view, briefly highlighted and focused. The highlight respects reduced motion.
- **Several launches.** A resumed Codex thread with several verified launch edges opens a small menu that lists each launch with its Claude session, lane and time, newest first.
- **Back.** Opening a parent pushes the current session, lane filter and scroll anchor onto a per-panel history. **Back** returns to the exact previous position. The history is kept in webview state and is cleared when the panel is disposed.
- **Unavailable.** A root session hides the action. An unresolved parent keeps the action visible and disabled, with a reason such as "Parent session not found yet" or "Launch not verified". A parent from a missing or disabled source explains that state.
- **Breadcrumb.** The session header shows the chain from the root, for example <code>dashboard / Fix export flow › Claude main › Bash › Codex validator</code>. Each segment opens that ancestor.

## Run statistics (Later)

A **Stats** tab next to Usage, scheduled after M3 (see [§15](15-milestones.md#later--run-statistics)). It uses the same Day, Project, Session and profile filters and the adapter selector, and shows only local observations. It has no cost, network or upload.

| Metric | Definition |
| --- | --- |
| Tool calls | Paired tool calls by tool, agent, provider and model. |
| Tool failure rate | Tool results with a recorded error or failed state, divided by paired results with a known outcome. Unknown outcomes are shown separately and not counted as success. |
| Command failure rate | Shell or exec calls with a recorded nonzero exit, divided by those with a recorded exit. Check commands are also shown on their own. |
| Loops | Count of Possible loop streaks, longest streak, and the tools that loop most. |
| Done without checks | Turns that ended with No checks after edits or Last check failed, as a count and as a share of completed turns that made edits. |
| Context pressure | Sessions that reached High or Critical, and compactions observed after a crossing. |
| Stops and interruptions | Confirmed Stop, interrupted and failed turns by agent and provider. |

## Background tasks

## Background tasks

The Agent map, sidebar, and **Background tasks** list show background entries with parent session, provider/profile, status, and an Open action. Each completion gets one notification with an Open action. The composer and run form offer **Run in background** for supported chat turns, tasks, and Codex runs. These entries start with **Show in main chat** off. The session toggle controls the default for its background entries and an item toggle explicitly overrides that default. Foreground entries show by default and can also be hidden individually. Opening a background transcript preserves the main chat view. Turning visibility on pulls the existing entry and recorded events into the main timeline, then follows new events. Turning it off removes those rows from main chat while the work stays inspectable and retains its Files and Usage attribution. Record only the visibility choices by stable IDs. Keep pending permission requests reachable through the background item and its status notification ([§9](09-chat.md)).

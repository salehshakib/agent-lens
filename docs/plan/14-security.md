# 14. Security and privacy

[← 13](13-tech-stack.md) · [Plan index](README.md) · [15 →](15-milestones.md)

- Use read-only handles for eligible Claude transcripts, agent metadata, task/spill outputs, opted-in quota snapshots, and Codex rollouts and index. Inspect lock filenames and metadata in watch mode. Exclude credential, secret, sandbox-secret, general history and operational database paths. A dedicated Codex model reader may project a minimal allowlist from its model cache and model-related config/profile fields in [§11](11-models.md). Keep general provider configuration and credential storage outside the transcript reader. Canonicalize approved roots, reject paths or reparse points escaping them, and revalidate user-invoked file or repo actions. Scope task/spill output to the owning session.
- Allowlist known schema fields before producing view data. Drop Claude request payloads and credential/organization attachments and Codex account-scoped metadata, along with credentials, injected instructions, encrypted/raw reasoning, raw tool schemas, connector identifiers, and opaque tool bodies. Redact recognizable secrets and sensitive path references before content reaches the webview, clipboard, notifications, or diagnostic interfaces. Apply the same boundary to stdout/stderr, quota metadata, background transcripts, and errors. Suppress command, output, diff and file actions tied to sensitive locations or unsafe payloads. Arbitrary free text can contain unlabeled secrets that pattern matching cannot identify. Default to full eligible redacted content and provide a private display mode to suppress free-form payloads. Keep raw payloads out of diagnostics in either mode.
- Render content through text nodes and narrowly scoped markup generated by the extension. Parse recorded diff hunks without applying them. Strip ANSI/OSC control codes. Keep remote images, arbitrary command links, executable HTML, and inline untrusted markup out of the UI. Use a webview CSP with <code>default-src 'none'</code>, <code>connect-src 'none'</code>, and nonce-approved bundled scripts plus narrowly scoped local stylesheet and asset origins. Use <code>asWebviewUri</code> and restrict <code>localResourceRoots</code> to packaged assets. [VS Code webview security](https://code.visualstudio.com/api/extension-guides/webview#security)
- Passive M1 observation makes no network calls and has no telemetry or remote assets. The relay and read-only auth probes stay within verified local scope. An explicit, verified Refresh limits action can invoke the official Claude CLI and its provider connection. User-launched agents and official sign-in flows use their configured providers. Each user authenticates with their own accounts. Keep credentials, OAuth, API keys, and authentication traffic within the official tools and environment. Exclude shared or bundled credentials and official login terminal output.
- The consented relay installer is a narrow settings writer for the selected profile. Read the status-line setting to chain it and preserve unrelated bytes and fields. Keep full relay stdin out of storage and diagnostics. Validate the settings path and write atomically with concurrent-edit detection. Leave the user's newer configuration intact on uninstall or conflict. [Claude settings](https://code.claude.com/docs/en/settings) · [Claude status line](https://code.claude.com/docs/en/statusline)
- Run signals and statistics use only the allowlisted, redacted projection. Call keys and result comparisons are hashes held in memory and are never written to disk, diagnostics or the webview. The statistics ledger stores counts, rates and source IDs, never prompts, commands, output or paths beyond the canonical project key. Check patterns and ignore globs come from user or machine settings only, never from repo-controlled files, and are matched against recorded commands as data without running a shell. Signals never trigger actions. Stop and other controls keep their own authorization rules.
- Store minimal local preferences, navigation state, saved profile metadata, background visibility flags, and opt-in quota snapshots. Content caches, composer drafts, queued messages, and account details are memory-only by default. Keep roots, CLI selection, source profiles and launch policy in user or machine settings, outside repo-controlled configuration. Use VS Code Workspace Trust to gate agent execution and interactive approval, including the default Full access Codex mode. Redacted, read-only navigation can remain available in Restricted Mode. [VS Code Workspace Trust](https://code.visualstudio.com/docs/editing/workspaces/workspace-trust)
- Treat webviews and provider records as untrusted inputs. Validate message shape, adapter/account scope, owner, capability, current turn, and trusted repo at the host boundary. Bind approval to a live request. A log record or launcher marker can link observed activity. Controls require independent live authorization and target verification. Limit a native approval bridge to an owned local stdio or vetted Windows IPC channel. Close or reject requests when the owner or channel changes. A user Stop action names the verified target and labels graceful and forced behaviors separately.

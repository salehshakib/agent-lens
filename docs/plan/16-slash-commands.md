# 16. M2 slash commands

## Chat entry point

Open Agent Lens into the Chat view of a conversation editor tab. Focus the composer and resolve the local project and active profile from the current workspace when unambiguous. Type `/` to see command names, short descriptions, and availability for the current chat. Submit a command from the same composer and show its result in an inline Agent Lens card. A card can link to the existing Timeline, Agent map, Files, Usage, and Background tasks views or open a recorded diff in VS Code.

Use `/resume` as the main route to recent and historical conversations. Start with the current project and offer **All projects** in the picker. Keep the Activity Bar sidebar, its all-project tree, and its existing actions available. Sidebar, notification, parent, and transcript navigation resolve to the same session and lane IDs as chat ([§4](04-session-model.md), [§8](08-ui.md)).

~~~text
Agent Lens / dashboard                                    Claude Code · Ready

You           Check the export fallback and run its checks.
Claude        The export checks passed.

/diff         Recorded changes                                  [Open Files]
              src/export.ts                                  [Recorded diff]

> /re
  /resume     Find and open a conversation
~~~

## Composer behavior

- Interpret the first non-whitespace character of the draft as the possible command prefix. A slash later in a normal prompt is ordinary text. A lone `/` opens the list and sends nothing. A leading `\/`, as in `\/usage in the README`, requests literal text. Keep the backslash on the wire if the adapter has no verified literal-text framing and Phase A confirms that the escaped input reaches the agent as text. If literal delivery is unavailable, preserve the draft and explain it. Never strip the escape and feed a bare slash through a provider's command parser.
- Use an accessible combobox with a list of matching commands. Rank exact names first, then prefix matches, then description matches. Show the route and concise unavailability reason when relevant. Use Up and Down to select, Tab or Enter with an active option to insert its spelling, and Escape to close the list while keeping the draft. Clicking an option also inserts it. Completion does not submit a command, change a setting, or start a worker.
- With no active option, Enter submits a complete command, or opens the list for an incomplete prefix. A full name without arguments is complete when the command supports a default view or picker. For example, type `/res`, select `/resume`, press Enter to complete it, then press Enter to open the picker. Use Shift+Enter for a newline and keep IME composition handling ahead of command shortcuts. The Send button uses the same parser as Enter. An unknown complete name returns suggestions and **Send as text** when the adapter supports safe literal delivery. No unmatched command is silently forwarded.
- Local command names are ASCII case-insensitive. Accept whitespace between a name and arguments. Each local handler validates the grammar in the catalog. Search terms and path filters consume the remaining single-line text verbatim after trimming outer whitespace. Strip one matching pair of double quotes around a filter if supplied. Treat backslashes in a path as characters. Reject unexpected arguments, extra flags, and extra lines with a usage hint. Native commands keep the provider's spelling and argument syntax. Apply the same size bounds as the composer and the active adapter.
- Local commands run alongside active work and can open a report, act on an explicit target, or adjust a future draft. They do not occupy a model turn or the prompt queue. Keep unrelated queued messages, ordinary draft text, and attachments bound to their original scope. A local result or validation error stays in Agent Lens. Do not send that command's text, attachments, result, or error to the provider. Native commands enter the owned channel only at a verified eligible boundary. Show a busy reason or an explicit queue action when that exact command can be queued. If a command does not accept attachments, keep them in the draft and show how to remove them or send them separately.

## Host dispatch and inline results

The host owns command resolution and effects. The webview sends a composer submission or a typed action for a card. Validate the command again with the active adapter, canonical project, profile/account generation, exact session, and any required lane, task or turn. Use opaque host-issued identifiers for selections and action targets. Reconcile revisions before performing an effect so an old card cannot act on a replacement run or the newly active profile. Guard duplicate submissions and double clicks for side effects. Keep loading, empty, denied, unavailable, and changed-target states visible at the command result.

Show an invocation and its result as a local timeline item with a stable ID and a scope label. Compact summaries can expand into the existing view content. Navigating to a full view preserves the chat draft and anchor. Live cards update from the same projections as the sidebar and tabs while their bound scope is valid. Re-evaluate actions on updates, and disable them when their evidence expires. Keep cards in view state and out of provider transcript files, usage totals, and prompt replay. Apply the same redaction, private-display preferences, and size limits as M1. Provider descriptions and results are sanitized text. Card actions come from the host contract.

The shared catalog defines names, argument schemas, capability requirements, and result models. Adapters supply scoped native command metadata and routes through the installed official CLI. Normalize CLI observations into the shared session, task, file, context, limits, and lifecycle events. Keep wire method names and protocol details in the adapter ([§17](17-chat-runtime.md)). Never execute a shell line through slash dispatch. Local actions that need a subprocess use a verified executable, typed arguments, and an explicitly scoped cwd and environment. Agent Lens never reads, copies, or writes provider credential or token files.

## Local command catalog

Bracketed arguments are optional. Arguments that identify a resource narrow the displayed choices. Selection binds the exact resource ID, and a subsequent action confirms any effect. A read-only command can open its card whenever there is observable data, including after a provider exits.

## Native commands, skills, and terminal handoff

1. Load the adapter's supported native command and skill descriptors from verified structured session initialization or another supported scoped catalog. Scope them to provider, binary version, account generation, cwd, and the current session capability generation. Show name, description, and arguments when the provider reports them. The startup snapshot can change after resume, project change, or a provider configuration update. Refresh from verified metadata when that happens. Opening `/` never starts an agent or runs a hook as a side effect.
2. Reserve the local catalog spellings even when a handler is unavailable. A local `/usage`, `/resume`, or `/clear` always dispatches locally. If a same-named provider command has a verified distinct route, show its qualified spelling, such as `/native:usage`, with the provider label. Resolve the exact registered provider name after `native:` and send the provider's original spelling and arguments through its verified route. Validate and deduplicate metadata. For conflicting descriptors with unclear identity or behavior, withhold dispatch and identify the ambiguity. Native metadata cannot register local commands or actions.
3. Pass through `/compact` as a native command only for a verified CLI/session combination that executes it in owned bidirectional JSON chat. Preserve any supported compaction instructions and show pending, completion, or error from the adapter. Update context when the provider reports a new scope or measurement. Apply the same routing to other supported native commands and advertised skills or custom commands. Keep their resulting prompt, streamed output, approvals, and tool calls in the ordinary provider lifecycle. Metadata that lists a command establishes discovery. Phase A establishes whether it runs with the needed semantics in the chosen transport.
4. For known interactive-only commands such as `/mcp` on the chat transport, show why the feature requires the official terminal and present an **Open official terminal** action where eligible. Handle known commands missing from the current transport and provider-rejected commands the same way. A provider rejection is shown once and is never auto-resubmitted as prose. Commands with no trustworthy route or mapping receive a specific unavailable result.
5. Bind a handoff to the exact approved installed executable, local cwd, saved home, and intended session. Check Workspace Trust, profile isolation, and current ownership again before any launch or attach. Use a documented official exact resume or attach route after verifying its eligibility and behavior. If Agent Lens currently owns the session, require a separate explicit release or verified handoff before another writer starts. If another interface owns it, direct the user to that interface when known. Explain that a fresh official terminal opens a separate conversation if no safe same-session route exists, and require explicit selection of that option. Preserve the chat's draft and queued work. Show the native slash spelling for the user to enter in the official UI. Do not inject arbitrary arguments into a shell, type a command into an unrelated terminal, or capture authentication prompts.

## Phase A capability checks

Use the installed Claude Code CLI and the future owned `claude -p` bidirectional JSON route. Record outcomes by version and scope before enabling the corresponding UI. The planning work does not run the CLI. For implementation, use authorized disposable profiles, sessions, and projects. [Runtime verification](17-chat-runtime.md#phase-a-permission-and-control-verification) · [Milestone checks](15-milestones.md)

- Verify catalog shape for built-ins, installed skills and project custom commands. Check descriptions, optional syntax metadata, collisions with local names, absent metadata, and permission/cwd changes. Exercise both local and qualified native routes. Confirm that ordinary and escaped text never runs a slash command through the CLI parser.
- Verify command acknowledgment and result boundaries, `/compact` with safe disposable instructions, a real reported skill, and an interactive-only command. Record what happens during active turns, approvals, and tool work before enabling native queue delivery. Confirm refusals preserve history and drafts without duplicate submission.
- Verify model, effort and Fast separately for fresh start, exact resume, and in-channel changes. Compare requested and effective values after a turn, including provider rejection and unsupported account/model combinations. Verify model catalog scope before and after switching profiles. Keep unproven routes disabled with a reason.
- Verify 5h and 7d events across ordinary turns, missing-window cases and account changes, and keep old profile samples out of the active scope. Check context without capacity, after compaction, and for individual lanes. Verify to-do evidence, background work and targeted Stop independently, including a child that finishes before its request can take effect.
- Exercise Enter, completion and Escape, blank `/`, invalid arguments, attachment preservation, stale card actions, project scope and All projects. Verify that opening `/resume`, `/clear`, or a read-only local card never starts or mutates a provider conversation. Confirm that exact continuation refuses an active external writer, and that the eligible terminal handoff does not start a second writer.

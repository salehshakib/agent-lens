# 15. Milestones, checklist, and verification

## M1 — View everything

1. Initialize the extension in the existing Agent Lens repo after approval. Set up the manifest namespace, strict TypeScript, esbuild and synthetic fixtures.
2. Build the adapter registry, version-aware Claude and Codex source adapters, settings per adapter, bounded byte tail, file generation detection, and polling reconciliation.
3. Implement the project/session/lane/turn reducers, tool and result pairing, ancestry, Claude-to-Codex launcher marker and nesting, and the Files activity index, including safe Open and historical diffs.
4. Ship the All projects tree with Live, Today, and scrolling Earlier groups. Add the unified redacted timeline, Files, read-only Agent map with detail popover, observed Background tasks, Usage, and quota/status surfaces for tokens, context fill, and limits. Show the default Claude 5h/7d gauges. Check the single-command refresh candidate, then ship the consented one-click chaining relay and uninstall.
5. Add run signals from [§4](04-session-model.md#run-signals): Possible loop with grouped repeated rows, Done without checks with its three outcomes, and High/Critical context levels with optional alerts off by default. Add Open parent with breadcrumb, multi-launch menu and Back history ([§8](08-ui.md#parent-navigation)), plus the Signals and Has warnings filters and the signal settings group.
6. Add read-only Accounts status for verified probes, saved-home profile scoping and Unknown states. Render actual observed model and effort next to session usage. Profile large histories, smoke-test external discovery, and package a clean local VSIX.

**Exit criteria.** Browse activity across projects, scroll into earlier history, and observe a live Claude turn, a running subagent, and a marked external Codex worker nested under its launcher. Verify live Agent map detail, ordered tool calls, Open transcript, full eligible redacted content, file provenance, and a recorded diff. Verify exact/unmatched links, stale/missing sources, restart and missed-watch recovery, and token deduplication. Show both providers' tokens, context fill, and profile-scoped limits with reset and unavailable states. On a disposable Claude profile, verify one-click relay install, unchanged prior status-line output, both windows, and uninstall restoring the prior value. Record the signed-in structured refresh result and enable Refresh limits only on a passing result. On disposable sessions, verify that a lane repeating the same call 3 times shows a live Possible loop that turns historical when a different call follows, and that changed polling output does not trigger it. Verify all three Done without checks outcomes and no badge after a passing check, including a Codex edit followed by a Claude check in the same turn tree and a docs-only edit that is ignored. Verify High and Critical context levels for Claude and Codex, the cleared level after compaction, and no level where capacity is unknown. From a Claude subagent, a Codex child thread and a linked Codex run, verify Open parent lands on the exact spawning row and Back restores the previous position. Install the VSIX in a clean VS Code profile.

The manual exit criteria above carry forward to [M2 Phase J](m2-implementation.md#phase-j--accounts-and-daily-flow-verification). The Timeline lane header action and refresh verification moved to [Phase D](m2-implementation.md#phase-d--chat-transcript-and-live-reconciliation) and [Phase E](m2-implementation.md#phase-e--keyboard-and-status-line), respectively. Verified read-only account probes and the license, extension icon and Marketplace preflight are tracked in Phase J.

## M2 — Chat-first conversations

1. Start with the approval and stream spike. On the installed official Claude Code CLI, verify bidirectional JSONL in print mode, acknowledgments, exact resume, per-turn limits, and the Windows cancellation scope. Prove that the native approval bridge gets a real request and that its decision reaches the exact tool call. Record which options, native user-input requests and task operations work on the tested version. If a safe essential route remains unverified, keep the capability unavailable and record the blocker before committing to the integration. [Chat runtime and controls](17-chat-runtime.md)
2. Open new and resumed conversations directly into Chat, with one editor tab per conversation, a composer and streamed replies. Use the shared session identity, events and projection for both live and historical content. Make `/resume` the primary path to compatible local sessions. Keep the All projects tree and M1 detail tabs reachable through the secondary navigation. [Chat design](09-chat.md) · [UI](08-ui.md)
3. Add the slash menu and inline cards with M1 read models. Show local commands, supported native commands and session-advertised skills with descriptions. Add folded tools and results, inline recorded diffs, todos, and in-place subagent and Codex blocks. Add keyboard behavior, the working line and the composer status line with effective model and effort, context fill and streamed 5h/7d limits. [Slash-command catalog](16-slash-commands.md)
4. Wire verified approvals and user input, then add attachments, the ordered queue, background runs and account controls. Enable exact-target Stop only for proven routes. Add the conversation-scoped `/codex` start/follow entry points for verified or handed-off official launches and linked run inspection. Deliver native login/logout and saved-profile switching with isolated homes. Preserve the user's Claude configuration and version-gate model, effort and Fast controls. [Implementation phases](m2-implementation.md)
5. Add **Open parent** to the Timeline lane header. Reuse exact spawning-row navigation and Back. [Phase D](m2-implementation.md#phase-d--chat-transcript-and-live-reconciliation)
6. Verify the installed **Refresh limits** action and local `/usage` parsing. Record whether the CLI emits `usage_report` and enable structured decoding only after verification. Keep chat stream limit samples independent. [Phase E](m2-implementation.md#phase-e--keyboard-and-status-line)
7. Verify official read-only account status for Claude and Codex, complete the deferred manual M1 exit checks in VS Code, and prepare the Marketplace release. The MIT license and extension icon are done in M2 via the parallel packaging PR and are verified in the release VSIX after merge. [Phase J](m2-implementation.md#phase-j--accounts-and-daily-flow-verification)

**Exit criteria**

- From an empty Agent Lens tab, send a prompt and read streamed replies in the same conversation. Use `/resume` to open a previously recorded terminal or panel conversation. Verify the exact ID, cwd and owning profile, read-only mode while another writer is active, and continuation after release. Use `/clear` to open a fresh conversation and return to the previous tab with its draft and scroll anchor preserved.
- Verify all local commands, the keyboard-driven menu and its descriptions, contextual availability, supported native passthrough and explicit handoff. Inspect M1 data inline and open the existing Timeline, Agent map, Files, Usage and Background tasks tabs from **Views**. Verify folded tool results, recorded Edit and Write diffs, todos, and linked runs in their originating turn. Check the M1 detail views and evidence navigation against the same history.
- When a turn runs, verify elapsed time, reported tokens, current effective model and effort, context level and independent 5h/7d updates from the same stream. Verify absent or stale data, a window reset, profile switching, and no double counting when matching file-tail records arrive. Exercise Enter, Shift+Enter, Esc, Shift+Tab, Up/Down, Ctrl+O, `!` and `@` with composer focus, menus and text selection.
- Demonstrate real Allow and Deny, stale request rejection, and independent turn interruption. Stop one verified owned background subagent or task while its parent and sibling keep running. Verify unavailable controls on an ordinary external Claude session and validate any registered background-session route independently.
- Attach a file, editor selection and pasted screenshot. Verify deterministic queue delivery and hold on a failed or interrupted turn. Run a turn and a task in the background, reach their pending requests from status surfaces, reveal their run blocks in Chat and receive one completion notification per item. Open a linked Codex run from its spawning block and `/codex follow`.
- Verify official login/logout and instant active-profile switching across two disposable homes. Pass the parity fixtures and the typecheck, test and build gates. Report any essential native parity or targeted Stop blocker before closing M2.
- From a Timeline lane header, verify **Open parent** reaches the exact launch row for a Claude subagent, Codex child thread and linked Codex run. Check multiple targets, unavailable parents, root lanes, destination focus and Back.
- In the installed extension, verify **Refresh limits** for a signed-in disposable Claude home against the official command's 5h/7d percentages and reset times. Record the observed format and confirm refresh runs without a model turn. Check both refresh paths, failures, freshness and profile attribution, including retention of prior eligible samples and no leakage between homes.
- Verify both providers' Accounts state and last check against official CLI status for isolated homes. Check signed-in, signed-out, missing or unverified output and any verified external mode. Unknown includes a reason when verification is unavailable.
- Complete and record the deferred M1 exit checks by hand in a clean VS Code profile. Inspect the exact release VSIX for the MIT license, 256 × 256 PNG icon and expected runtime files. Confirm the package clears Marketplace preflight and the publisher can release it.

## M3 — Codex control and chat

1. Add Codex Start and exact Follow up via the supported CLI, owned stdout/process supervision, Run in background and error recovery. Enable the shared model/effort picker, isolated homes, official per-profile account actions and instant switching. Use Full access by default on fresh and resume with Workspace write as the per-run choice.
2. Deliver Stop for verified owned and external Windows Codex workers through the Agent map and eligible run surfaces. Correlate exact rollout and lock identity, test shared processes, process identity races, descendant cleanup, watchdog/retry behavior, and permission denial. Enable each graceful or force mode only for its verified scope and applicable policy.
3. Extend the conversation-scoped Codex launch and observation from M2 to independent Codex conversation control. Feed one-turn <code>exec</code>/<code>resume</code> into the shared chat UI if it satisfies core interaction. Test app-server stdio for richer deltas, exact resume, explicit request approval, interrupt, <code>model/list</code> and account status. Turn on each capability only after versioned verification.

**Exit criteria.** Start and resume the exact Codex thread under its owning profile. Verify actual Full access defaults and Workspace write selection in both directions across fresh and resumed turns. Toggle a background run into main chat and verify scoped accounting and a single finish notification. Complete official login/logout/switch across two disposable homes and test writer contention. Stop a verified owned and a verified dedicated external worker without affecting another run, and verify controls for shared, stale, ambiguous, or denied cases. If either Stop path fails validation, report the specific blocker before closing M3. If chat is feasible, reuse the composer and shared transcript renderer. Otherwise document the exact protocol gaps while preserving the delivered controls.

**Exit criteria.** Discover and show a recorded Gemini CLI session and observe an append or rewrite on Windows through the common registry and UI. ## Later — Run statistics

Scheduled after M3. M1 already collects the signal and tool outcome counts in the ledger, so this milestone adds the view and its backfill.

1. Extend the ledger backfill to tool outcomes, command exits, loop streaks, Done without checks outcomes, context crossings and stop/interrupt outcomes for all discovered history, using the existing bounded background queue.
2. Build the Stats tab from [§8](08-ui.md#run-statistics-later) with the shared filters, provider columns, drilldown to sessions and evidence rows, accessible tables and coverage labels.
3. Make it work for every enabled adapter through the same normalized events. That includes Gemini CLI once M4 is done, with unavailable metrics labeled per adapter.

**Exit criteria.** On synthetic and disposable history, each metric matches a hand count from its fixture, unknown outcomes stay out of the rates, a file rewrite or replay does not double count, and drilldown reaches the exact rows. Large histories stay responsive during backfill and the view works offline.

## Testing approach for implementation

- **Synthetic fixtures and adapter unit tests.** Cover the observed variants for both providers, future fields, dropped request/credential records, UTF-8 and CRLF boundaries, partial EOF/JSON, line caps, malformed records, duplicate replay, rewrites, and large compactions. Include Claude sidechains, detach/resume, out-of-order child metadata, exact and ambiguous spawning/tool results, persisted text spills and file-history deltas. Keep fixture identities, paths, prompts, and secret-shaped values synthetic.
- **Lifecycle, attribution, and Files tests.** Cover outputs before calls, repeated identical commands, compacted transcripts, multi-turn resume, task scheduling versus completion, terminal and recoverable errors, writer/marker staleness, and absent child logs. Verify Claude task ID plus Codex UUID, JSON header, resume turn, redirected or missing header, delayed match, cross-repo roots, and competing tasks. Check path canonicalization, rename, missing preimage, proposed/failed patch, shell-only mentions, sensitive paths, and preferring valid recorded diffs.
- **Usage tests.** Cover multi-block Claude responses, parent/child aggregation, copied usage records, Codex exact and fallback cumulative scopes, missing/unknown fields, repeated response IDs, token breakdowns, and daily timezone attribution across resumes. Test Codex slot reversal, null info or quota, bucket separation, missing access, relay concurrency, independent Claude windows, structured refresh fallback, stale samples, profile/account switches, and one warning per threshold and reset.
- **Run signal tests.** Loop streaks across text and reasoning rows, broken by a different call, per lane only, at a custom threshold, with polling repeats that have unchanged versus changed results, across resume and compaction, and with partial or ambiguous rows. Done without checks with edits and checks split across subagents and linked Codex runs, inferred or failed edits, ignored globs, custom patterns, unknown exit status, late child reconciliation, and non-completed turns. Context levels at the exact thresholds, invalid threshold settings, stale samples, compaction drop, one alert for a jump through both levels, and no level without capacity. Open parent targets for each relation, several launch edges, unresolved and missing parents, and Back history.
- **Integration checks.** Simulate incremental writers and watcher errors, day rollover, stale markers, late index updates, rotation, multiple repos and old-session resume. Verify minimum path access and a bounded polling cadence. In M2, replay scrubbed stream fixtures for acknowledgments, partial replies, queue ordering, stale approvals, mixed live and file copies, limits, model changes, cancellation and session ownership. In M3, use fake CLI/app-server output for args, stderr and errors, resume and active writers. Validate catalog filtering, nested efforts, allowlisted auth results, account change invalidation, and the M4 fixture adapter. Keep repeatable checks offline.
- **Windows and VS Code manual checks.** After implementation authorization, use disposable repos/sessions/profiles for real CLI tests. Follow the workflow and auth/stop acceptance criteria for each milestone, preserving the user's real configuration. Test keyboard navigation, narrow layouts, themes, long-session scroll, missing sources, CSP, trust, and clean-profile VSIX installation.

## Pre-distribution checklist

- Review current Anthropic and OpenAI terms and documentation for the exact distributed local workflow, unmodified user-installed CLI binaries, provider authorization, and provider names/branding. Record the result before distributing the VSIX. Resolve any terms blocker before release. [Claude Code legal and compliance](https://code.claude.com/docs/en/legal-and-compliance) · [Terms for using Codex](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan)
- Verify new users can sign in to their own Claude and Codex accounts in the official CLI flows, switch their independently signed-in homes, and finish the supported smoke flow. Inspect the VSIX for credentials, private data, fixture content, and bundled provider binaries.
- Verify the Marketplace identity, version, listing and release VSIX under [M2 Phase J](m2-implementation.md#phase-j--accounts-and-daily-flow-verification). If the README or changelog uses images, confirm they resolve over HTTPS and use a supported format. Marketplace allows SVG badges only from trusted providers. ## Decisions

| Question | Decision |
| --- | --- |
| Q1. Sidebar default | All projects, grouped by project and Live / Today / Earlier, with older rows loaded on scroll. |
| M2 default surface | Chat opens first with one tab per conversation. `/resume` opens conversations. Slash cards and the composer status line surface the current conversation's data. The tree and existing detail tabs stay available. |
| Q2. Claude limits | M1 shows both windows by default. Ask once and install the chaining relay in one click with uninstall. M2 verifies the existing single-command <code>/usage</code> refresh and validates the structured candidate for explicit refresh if the installed CLI supports it. [Phase E](m2-implementation.md#phase-e--keyboard-and-status-line) |
| Q3. Claude-to-Codex link | Use the <code>codex-first</code> startup marker convention to nest each verified run under its launching Claude session and lane. |
| Q4. Main chat content | Full eligible content with secrets masked by default. Run in background keeps selected turns, tasks and Codex runs out of main chat, with separate status, open and finish notification. Show in main chat is available per item and session. |
| Q5. Usage display | Tokens, context fill and limits only. |
| Q6. Distribution and sign-in | Distribute Agent Lens with the native CLI route. Each user signs in to their own Claude and Codex accounts through the official CLIs. Terms review is a release checklist item. |
| Q7. Parity | Use the user's daily workflows listed in M2 parity fixtures. |
| Q8. Accounts | Save separate <code>CLAUDE_CONFIG_DIR</code> and <code>CODEX_HOME</code> profiles, show the active one per adapter, and support instant switching with native sign-in/out and verified state isolation. |
| Q9. Codex launch permission | Full access by default on Agent Lens fresh runs and resumes, with Workspace write available per run. |
| Q10. Next adapter | Gemini CLI in M4. |
| Run signals and statistics | Added 23 November 2026. M1 ships Possible loop, Done without checks, High/Critical context levels and Open parent as view-only signals that never change agent behavior. Run statistics follows later, after M3. |
| Agent map and Stop | Provide a map and agent detail popover with Open transcript and Stop agent. M2 delivers targeted Stop for eligible owned Claude subagents/tasks. M3 delivers verified owned and external Codex worker Stop. Enable the action per target and explain unavailable cases. |

**Extension host.** Own generic discovery and tailing, the adapter registry, correlation, redaction, shared aggregates, notifications, and process supervision. Adapters own provider schemas, translation and protocol behavior. They run independently and can fail separately with partial coverage. Hold only a bounded set of materialized timelines. Use typed messages with opaque IDs for host-validated actions. Activate in the local UI extension host so a remote VS Code workspace cannot redirect a log reader or launch a Windows process against a remote path. The webviews render normalized events, capabilities and adapter-supplied labels. [VS Code workbench integration](https://code.visualstudio.com/api/extension-capabilities/extending-workbench) · [VS Code webview API](https://code.visualstudio.com/api/extension-guides/webview)

**Webviews and session tree.** Use one editor panel that can switch sessions and a sidebar webview view for quota glance and a paged session tree. The sidebar can observe viewport scroll for Earlier pagination and retain VS Code keyboard and theme conventions. Render snapshots and sequenced, batched row updates. Request pages and expanded payloads by ID, keep only redacted view data in memory, and rehydrate from the host when restored. Save navigation state such as session ID, scroll anchor, and filter with the webview state APIs. A sequence gap requests a fresh window. Disposing a panel removes its listeners and detail subscriptions. Catalog and quota observation can continue at their lower background cadence. [Webview messaging and persistence](https://code.visualstudio.com/api/extension-guides/webview)

## Discovery and incremental tailing

1. Resolve and validate allowlisted Claude and Codex roots independently for each saved source profile. Subscribe to change hints before the initial scan and reconcile hints received during enumeration. Skip symlinks and directory junctions that escape approved roots. Enforce path pattern and provider ID checks. Enumerate Claude projects and session directories and Codex date directories with bounded concurrency. Prioritize recent files, matching liveness markers, and selected or active lanes. Build the sidebar from lightweight metadata/head/tail reads. Defer full replay and usage backfill for older sessions to a background queue.
2. Start with Node <code>fs.watch</code> on Claude projects and Codex sessions in recursive mode. Watch small metadata roots such as the Codex index parent and lock directory separately, and subscribe to known active Claude task directories and the opted-in bridge location. Avoid one watcher per transcript or scanning the whole temporary directory. Treat <code>change</code> and <code>rename</code> as hints. The filename can be absent, events can collapse, a moved directory can stop reporting, and deletion on Windows can yield <code>EPERM</code>. A missing or ambiguous filename schedules a scoped rescan. Rebuild a failed watcher after a re-stat with backoff.
3. Debounce bursts, re-stat, and enqueue one reader per file generation. Poll independently. Initial targets are 500–1,000 ms for selected/live files, 2–5 seconds for recent discovery and relevant metadata when the view is active, and a bounded slower sweep of known older files and folders. Back off when idle. Reconcile after sleep, project changes, midnight rollover, resume in an old folder, and the appearance of a previously missing source root. Reread small replaced metadata atomically by file generation. Keep task prefix probes bounded and watch temporary files only while evidence is relevant.
4. Track absolute byte offset, generation identity, preceding bounded overlap where useful, and pending bytes after the last newline. Read appended chunks with positional I/O. Split on LF in bytes, strip CR for CRLF, handle an initial BOM, then decode complete UTF-8 lines. A multi-byte character, JSON escape, or partial object may span reads. Preserve the final partial line for a subsequent append. Optionally accept a valid newline-less final object once a stable ended file has been verified. Establish a committed offset for complete lines and keep the pending bytes bounded.
5. When identity changes, the file shrinks, or an overlap check detects a rewrite, reset that generation, reparse and reconcile by thread identity. Track <code>dev</code>/<code>ino</code> when meaningful, size and creation metadata, and a bounded content check as needed. A changed offset defines a replay, so do not append the replacement history to the old view. Handle access denied, sharing violations, and transient disappearance as retryable read state. Never create a missing file or retain handles that unnecessarily impede writer cleanup. [Node filesystem watch caveats](https://nodejs.org/download/release/v22.13.0/docs/api/fs.html#caveats)

## Parsing, merging, and resource budgets

- Use small type guards at provider adapter boundaries. For syntactically invalid complete lines, increment a diagnostics count and continue. Quarantine malformed nested arguments to a generic tool row. Recognize legacy variants by shape and track the emitter version for compatibility diagnostics. Unknown types can produce a bounded count with a safe type label. Do not log the line, unknown payload, exception text that embeds content, or unknown data keys.
- Read in chunks, initially 64–256 KiB. Set a configurable internal ceiling of 16 MiB per JSON record for the first implementation, with a diagnostic placeholder and a discard-until-newline mode for bigger records. That includes the largest observed record while capping allocation. Parse large lines off the extension-host event loop if profiling shows stalls. Discard ignored context and duplicate embedded history as soon as the record is classified. Treat these figures as initial budgets to verify.
- Pair Claude blocks and results through their explicit IDs, grouping provider responses while preserving each block. Pair Codex function/custom outputs by <code>(thread, turn, call_id)</code>. Match a structured <code>item.id</code> to an explicit equivalent ID when available. An otherwise unique match can use kind, turn, command or text, and occurrence order. Many observed Codex IDs did not match verbatim. When matching is ambiguous, retain the structured row and group available sanitized details under a collapsed turn section without merging unrelated executions.
- For a panel-owned worker, register the <code>thread.started.thread_id</code> when stdout provides it. For resume, the expected ID is already known. A mismatch blocks control and surfaces an explicit diagnostic. Adapt <code>turn.started</code>, <code>turn.completed.usage</code>, <code>turn.failed</code>, <code>error</code>, and <code>item.started</code>/<code>item.updated</code>/<code>item.completed</code> to a provisional stream. Use stream-scoped identities and monotonic local sequence. Merge by explicit IDs when available, otherwise match uniquely by content and ordinal within the same turn. Avoid sending duplicate cards as stdout and rollout catch up. Enable live updates only at the granularity the stream actually emits. External rollouts often emit completed records, so individual command output may appear when Codex writes the result.
- Use file order as authoritative within a rollout and explicit relations across files. For mixed agent views, use event time with deterministic tie-breaks and preserve each thread's internal order. A late child or matched tool result updates its row without changing the scroll anchor.
- Batch updates about every 75–150 ms when visible. Retain row summaries and positions for older pages, evict large bodies, and fetch sanitized body data lazily. Keep the most recently selected sessions in a bounded cache and keep only lifecycle summaries for other sessions. Use pages of roughly 100 rows plus an overscan window for long timelines. Cap initial previews and load longer text or hunks by page. Do not precompute every repo diff or keep an entire historical directory in memory.
- Schedule usage backfill and file-index enrichment behind live observation, with per-cycle time/IO budgets and resumable progress within an extension session. Store sparse record locations and bounded summaries instead of raw text. Keep daily/project summaries as the ledger compacts and compute drilldowns lazily. Run signals and tool outcome counts use the same ledger pattern: bounded counts per day, project, profile, adapter, model and lane with source IDs, no raw text. Track which files and generations reached committed offsets so a replacement can invalidate and rebuild affected aggregates without double counting.
- Targets on the reference machine are first sidebar rows within one second from a warm start, normally visible append updates within two seconds, and smooth scroll on a 1.2 MB session. Profile 8 MiB records, a 42 MiB Claude transcript, and dozens of live lanes alongside discovery of 1,800-plus child files. Check responsiveness during quota backfill and verify polling fallback cadence. These are implementation targets.

## Adding a new agent

Register each adapter with its permanent agent ID, display label, branding token, default source discovery rules, version probe, and capabilities. Claude Code and Codex are ordinary entries in the same registry. The host owns filesystem/process primitives, eligibility checks and storage. Each adapter supplies only its own formats, command arguments, or supported protocol behavior.

| Adapter operation | Contract |
| --- | --- |
| <code>discoverSessions</code> | Given an approved local source and cancellation signal, return catalog metadata, stable session/lane IDs and authorized source descriptors. Report coverage and unsupported versions. |
| <code>watch</code> / tail | Provide relevant directories, paths and cursors, or an authorized structured stream. Reuse the shared byte tail and discovery scheduling where applicable. Surface replacement, live and partial states independently. |
| <code>parseRecords</code> | Translate complete input records into normalized events. Pair protocol IDs, provide attribution and source evidence, and discard disallowed content before any view model is produced. For each tool call, supply a normalized argument key, a polling flag for tools that only observe other work, and the recorded exit status or error state of its result, so the host can compute run signals ([§4](04-session-model.md#run-signals)). |
| <code>usage</code> and <code>limits</code> | Emit normalized usage and limit samples from supported sources. Describe token category inclusion rules, quota windows, and coverage. Derive account snapshot scope without reading credential identifiers. |
| <code>linkToParent</code> (optional) | Emit an attributed edge or narrowly scoped evidence to the host joiner. A link can cross adapters. The host validates the target, canonical identity, timestamps, and cycles. |
| <code>start</code>, <code>followUp</code>, <code>stop</code> (optional) | Receive an explicit request scoped to a profile/project/session with model parameters and a cancellation signal. Return a managed handle or a typed outcome with verified identity. |
| <code>chat</code> (optional) | Start or resume a channel, send messages/attachments, emit acknowledgments and normalized live events, handle supported approval/user-input requests, and interrupt or close the owned channel. Publish eligible slash commands, models and attachment types as supported. |
| <code>modelSelect</code> (optional) | List verified or provenance-labeled model choices, capabilities and effort/speed options for the active profile, and translate per-run requests into provider-supported arguments or protocol fields. |
| <code>auth</code> (optional) | Report provider-owned account status for a saved home and expose verified Sign in and Sign out. Launch the official flows and return an allowlisted status update. The host switches the active saved profile independently of provider authentication. |

The common event envelope contains adapter/source profile, project, session and lane IDs, optional turn/parent IDs, stable source key or cursor, timestamp, and event kind. All renderers map the kind to UI. The adapter ID supplies labels and scoping only. Native identifiers used for correlation stay in host state where a webview can use opaque IDs.

| Normalized event | Content consumed by the shared model and UI |
| --- | --- |
| Session / turn | Identity, start or end, title, effective model/effort, project, lifecycle evidence, and optional duration. |
| Message / reasoning | Role, content parts, phase, partial/final, optional visible thinking or summary, and redaction state. |
| Tool call / tool result | Stable call ID, display name, vetted arguments, result state, timing, and bounded result reference. |
| File change | Path identity, read/change/reference, status, source call, recorded patch, and completeness. |
| Subagent / child run | Parent lane and spawning call, child identity, relation, evidence and relationship phase. |
| Usage sample / limit sample | Scope, response or snapshot ID, units, observed time, categorized counts or percentage, provenance and reset when available. |
| Status change | Prior/new supported state, scope, reason, and evidence freshness. |
| Chat acknowledgment / permission or user input request | Message or request ID, owning channel/turn, pending options, validated proposal summary, and expiration. No execution request comes from a transcript. |
| Run signal (host-derived) | Kind (possible loop, done without checks, context level), scope, live or historical state, evidence row IDs, count or level, and reason. The host derives it from the events above. Adapters never emit it directly. |

The descriptor advertises <code>watch</code>, <code>usage</code>, <code>limits</code>, <code>chat</code>, <code>modelSelect</code>, <code>auth</code>, and separate availability for start, follow-up, stop, interrupt, attachments, approval, and slash commands as applicable. Auth has per-operation availability, so status can ship before sign-in actions. Resolve flags against the observed binary/protocol, rollout source, profile, and session ownership. The Agent map always shows Stop agent with the eligibility reason when unavailable. Hide unsupported controls on other surfaces where no eligibility hint is needed. The host validates the same conditions on invocation regardless of the UI. The shared views consume the capability and reason for the current target.

<code>agentLens.agents</code> is a user/machine setting keyed by adapter ID. Each entry has <code>enabled</code>, an optional observation-only <code>logRoot</code>, and optional default model, reasoning effort and supported mode preferences. Approved saved homes supply both the profile-scoped discovery root and command environment. A discovery override does not grant controls or account attribution. Validate roots and companion paths inside approved boundaries. Disabling an adapter removes its view and watchers without automatically stopping an owned process. Re-enable with a fresh catalog reconciliation. Defaults enable Claude Code and Codex when their source roots are usable.

**M4 Gemini CLI adapter.** Google documents automatic project-scoped sessions under <code>~/.gemini/tmp/&lt;project_hash&gt;/chats/</code>, which defaults to <code>%USERPROFILE%\.gemini\tmp\&lt;project_hash&gt;\chats\</code> on Windows. With <code>GEMINI_CLI_HOME</code>, resolve <code>&lt;override&gt;/.gemini/tmp/…/chats/</code>. Upstream source shows <code>session-*.jsonl</code> records with session metadata and messages. Gemini CLI was absent from the checked command path, so validate the installed release's Windows paths, project bucket mapping, session format, rotation/rewrite behavior and fields before enabling an adapter. Do not decode a project path from its bucket name alone. [Gemini session management](https://geminicli.com/docs/cli/session-management/) · [Gemini home isolation](https://geminicli.com/docs/cli/enterprise/#user-isolation-in-shared-environments) · [Gemini session record types](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/services/chatRecordingTypes.ts)

Implement a version probe, <code>discoverSessions</code>, <code>watch</code>/tail and <code>parseRecords</code> for eligible session files. Use the full recorded session ID and verified project/profile evidence to normalize prompts, replies, tool activity, and supported Files entries. Implement <code>usage</code> from verified recorded token categories and mark incomplete coverage. Treat <code>limits</code>, <code>linkToParent</code>, <code>start</code>, <code>followUp</code>, <code>stop</code>, <code>chat</code>, <code>modelSelect</code>, and <code>auth</code> as unavailable until an applicable interface and version are verified. Documented exact-ID resume and headless structured events are candidates for later controls. Keep credentials, checkpoints, and general Gemini state outside the session reader. [Gemini session management](https://geminicli.com/docs/cli/session-management/) · [Gemini headless mode](https://geminicli.com/docs/cli/headless/)

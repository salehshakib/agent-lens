# 3. Codex data sources and schema

[← 2](02-claude-code-data.md) · [Plan index](README.md) · [4 →](04-session-model.md)

## Local evidence

- Verified VS Code 1.147.0, Node 22.13.0, and Codex CLI 0.170.0 from version output. Inspected the installed npm command and JavaScript launcher. On Windows the shim starts the native Codex executable as a child.
- Inventoried 139 rollout files, totaling about 163 MiB, and did a deeper field-shape pass over 15 representative files. The inventory included 23 rollouts stamped with CLI 0.170.0 and older records down to 0.58. A single record reached 8,153,717 bytes. Six terminal records carried a structured error.
- All 102 distinct thread IDs in the observed session index matched a rollout, and some rollout threads had no index entry. A sampled child thread had a different thread and session ID. Two zero-byte writer-lock files existed at the time of inspection. One matched a current rollout. File presence by itself cannot identify the owner or establish that a turn is running.
- The three SQLite files had WAL-format headers and live sidecars. Inspected their filesystem metadata and headers without opening a SQLite connection. A Windows CIM process query returned access denied, so live process ownership and cancellation were unverified. No sessions were started, resumed, or stopped during investigation.
- Context7 was unavailable in the session. CLI syntax below comes from installed help, and platform behavior comes from primary documentation. The upstream writer-lock source is a reference for the design gate because the exact installed-version source could not be fetched. [Codex CLI reference](https://learn.chatgpt.com/docs/cli/reference) · [Codex writer-lock implementation](https://github.com/openai/codex/blob/main/codex-rs/rollout/src/writer_lock.rs)

## Inputs and precedence

| Source | Observed structure or documented purpose | Planned use |
| --- | --- | --- |
| <code>$CODEX_HOME/sessions/YYYY/MM/DD/rollout-…-&lt;thread-id&gt;.jsonl</code> | Local UTF-8 JSONL with an outer <code>timestamp</code>, <code>type</code>, and <code>payload</code>. A dated directory represents discovery placement, so a resumed thread can append to an older path. | Primary source for runs started anywhere that use the selected Codex home and persist rollouts. Discovery is independent of VS Code's workspace and launch ownership. |
| <code>$CODEX_HOME/session_index.jsonl</code> | <code>id</code>, <code>thread_name</code>, <code>updated_at</code>. | Advisory title and recency enrichment. Pick the newest valid entry per thread. Use rollout discovery independently so untitled workers and child agents are visible. |
| <code>$CODEX_HOME/history.jsonl</code> | <code>session_id</code>, <code>ts</code>, <code>text</code>. | Exclude from runtime reads. It duplicates some user content, groups on a different key, and provides no turn outcome or writer evidence. |
| <code>$CODEX_HOME/thread-writer-locks/&lt;thread-id&gt;.lock</code> | A zero-byte filename marker. Upstream opens the file and takes an OS lock. It cleans up on normal drop and can remove stale files on a later start. | Metadata-only signal during watch-only. Correlate it with lifecycle and recent activity. Never open it for locking, delete it, or infer a PID from its contents. [Writer-lock source](https://github.com/openai/codex/blob/main/codex-rs/rollout/src/writer_lock.rs) |
| <code>state_5.sqlite</code> | Codex state and thread metadata. Upstream uses thread rows for fields such as rollout path, recency, and history mode. | Useful if a later supported metadata reader needs to reconcile an index or archive discrepancy. Keep it outside the first release's reader. It provides no reliable proof of a live OS process. [Codex thread metadata storage](https://github.com/openai/codex/blob/main/codex-rs/state/src/runtime/threads.rs) |
| <code>thread_history_1.sqlite</code> | Codex paginated thread history. Observed rollouts marked <code>history_mode: paginated</code> still contained timeline records. | A possible coverage supplement if a later release exposes a thread with incomplete JSONL history. Prefer the documented <code>thread/read</code>, <code>thread/turns/list</code>, and <code>thread/items/list</code> interfaces after a separate compatibility check. [Codex storage implementation](https://github.com/openai/codex/blob/main/codex-rs/state/src/sqlite.rs) · [Codex App Server](https://learn.chatgpt.com/docs/app-server) |
| <code>logs_2.sqlite</code> | Codex operational logs. | Exclude from runtime reads. Operational log messages increase sensitive data exposure and are unnecessary for the timeline. [Codex storage implementation](https://github.com/openai/codex/blob/main/codex-rs/state/src/sqlite.rs) |
| <code>codex exec --json</code> stdout, stderr, and process close | Documented JSONL events on stdout, with a separate stderr stream. The extension can observe exit for a worker it launched. | Supplement the rollout for early activity, in-flight updates, and explicit errors. Feed both inputs to one session reducer. Retain shell output that Codex itself captures as part of tool events. [Codex non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode) |

Resolve Codex roots from registered profile homes ([§12](12-accounts.md)). Discover a host-visible <code>CODEX_HOME</code> or the current Windows user's <code>.codex</code> directory for the default profile. Register a Git Bash override outside those homes explicitly. Watch only eligible rollout paths, index metadata, and lock markers. If archive support is approved, add a separate allowlisted <code>archived_sessions</code> source when it exists. There was no such directory in the inspected home.

Concurrent SQLite reads are supported under WAL with SQLite's locking protocol and appropriate access to sidecars. SQLite can need sidecar creation on open, and long readers can hold back checkpoints. <code>immutable=1</code> assumes files cannot change, so it is unsuitable for a live database. For a later offline schema investigation, use a consistent snapshot, including committed WAL state as needed, and open the snapshot read-only. The extension can deliver the observed watch workflow without touching live databases. [SQLite WAL documentation](https://sqlite.org/wal.html#read_only_databases)

## Rollout envelope and top-level records

Field paths in this section are relative to <code>payload</code>. Fields are optional unless needed to identify a particular record. The inventory spans CLI versions, so a field present in one variant can be absent in another.

| Outer <code>type</code> | Observed fields | Normalization and UI |
| --- | --- | --- |
| <code>session_meta</code> | <code>id</code>, <code>session_id</code>, <code>timestamp</code>, <code>cwd</code>, <code>runtime_workspace_roots</code>, <code>originator</code>, <code>cli_version</code>, <code>source</code>, <code>thread_source</code>, <code>model_provider</code>, <code>history_mode</code>, <code>git.branch</code>, <code>git.commit_hash</code>, <code>git.repository_url</code>, <code>forked_from_id</code>, <code>parent_thread_id</code>, <code>agent_nickname</code>, <code>agent_role</code>, <code>agent_path</code>, <code>multi_agent_version</code>, <code>subagent_history_start_ordinal</code>, <code>context_window.window_id</code>. <code>source</code> can be a string or an object with <code>subagent.thread_spawn</code>, which includes <code>parent_thread_id</code>, <code>agent_nickname</code>, <code>agent_path</code>, <code>agent_role</code>, <code>depth</code>. | Catalog and ancestry. Key the catalog on <code>id</code>, which matched the filename UUID in the shape sample. Keep <code>session_id</code> as a grouping hint. Use <code>parent_thread_id</code> or the spawn metadata for the actual parent edge. Render repo and optional branch plus a friendly source label. Exclude account metadata, instruction bodies, and remote URLs from the UI. |
| <code>turn_context</code> | <code>turn_id</code>, <code>root_turn_id</code>, <code>cwd</code>, <code>model</code>, <code>effort</code>, <code>summary</code>, <code>collaboration_mode.mode</code>, <code>collaboration_mode.settings.model</code>, <code>collaboration_mode.settings.reasoning_effort</code>, <code>workspace_roots</code>, <code>permission_profile</code>, legacy <code>sandbox_policy</code>, <code>approval_policy</code>. | Update turn metadata. <code>summary</code> here describes the summary setting. Reasoning text comes from reasoning records. Drop instructions and policy internals from the webview DTO. |
| <code>world_state</code> | <code>full</code>, <code>state</code>, including <code>state.model.model</code>, <code>state.agents_md</code>, <code>state.environments</code>, <code>state.permissions</code>, <code>state.tools</code>. | Internal context. Ignore the body for UI and title extraction so injected instructions and tool definitions cannot enter the timeline. |
| <code>event_msg</code> | <code>type</code> plus variant fields listed below. | Source for turns, structured completed items, and fallback usage snapshots. |
| <code>response_item</code> | <code>type</code> plus variant fields listed below. | Source for transcript, tool call/output pairing, and reasoning summaries. Where present, <code>internal_chat_message_metadata_passthrough.turn_id</code> gives explicit turn association. |
| <code>token_usage_record</code> | <code>thread_id</code>, <code>turn_id</code>, <code>session_id</code>, <code>root_turn_id</code>, <code>response_id</code>, <code>usage</code>, <code>turn_token_usage</code>, <code>thread_token_usage</code>. | Update per-response, turn, and thread usage. Show the latest applicable snapshot in the header and retain selected turn usage for older turns. |
| <code>inter_agent_communication_metadata</code> | <code>trigger_turn</code>. | Internal attribution hint. A visible message requires an actual agent-message record. This boolean alone generates no timeline row. |
| <code>compacted</code> | <code>message</code>, <code>replacement_history</code>, <code>compaction_response_id</code>, <code>latest_token_usage_record</code>, <code>window_number</code>, <code>first_window_id</code>, <code>previous_window_id</code>, <code>window_id</code>, <code>replacement_history_metadata</code>, <code>retained_context</code>, <code>resume_metadata.last_started_turn_id</code>. | Optional collapsed context-compaction marker. Keep the existing transcript, count the marker once, and skip rendering or replaying the embedded replacement history. The embedded usage snapshot is a fallback only if matching standalone snapshots are missing. |

| <code>turn_aborted</code> | <code>turn_id</code>, <code>root_turn_id</code>, <code>reason</code>, <code>started_at</code>, optional <code>completed_at</code>, <code>duration_ms</code>. | Interrupted for the observed <code>interrupted</code> reason. | <code>thread_settings_applied</code> | Optional <code>thread_id</code>. <code>thread_settings.model</code>, <code>reasoning_effort</code>, <code>cwd</code>, <code>runtime_workspace_roots</code>, <code>model_provider_id</code>, <code>collaboration_mode.mode</code>, <code>collaboration_mode.settings</code>, <code>reasoning_summary</code>, <code>approval_policy</code>, <code>permission_profile</code> inside settings. | Populate effective settings, scoped to the owning thread and the following or active turn according to record order. | <code>token_count</code> | Nullable <code>info</code> with <code>total_token_usage</code>, <code>last_token_usage</code>, <code>last_usage_includes_reasoning</code>, <code>model_context_window</code>. | <code>user_message</code> | <code>message</code>, <code>text_elements</code>, <code>images</code>, <code>local_images</code>. | Legacy user prompt fallback. Render sanitized text and an attachment count when known. Skip loading attachment paths. |
| <code>item_completed</code> | <code>thread_id</code>, <code>turn_id</code>, <code>item.type</code>, <code>item.id</code>, optional <code>started_at_ms</code>, <code>completed_at_ms</code>, <code>content_token_count</code>. | Upsert the structured item using its thread, turn, and item ID. Per-item token count is distinct from usage. Render the following item variants. |

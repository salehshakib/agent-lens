# Agent Lens

Build plan · 23 November 2026 · Approval required before implementation

## 1. Goal and scope

Agent Lens is a local VS Code extension for watching and chatting with coding agents. It will replace the user's daily workflow in the official Claude Code VS Code panel, including prompts, permissions, model choices, and account controls. Claude Code and Codex are the first two adapters. The first milestone delivers observation of both, including Claude conversations, each subagent's activity, files, external Codex runs, and usage. A Claude Bash task and the Codex run it launched appear together when local evidence establishes the link.

- While Claude Code is working, I want to read its messages and see the commands and edits from the main session and each subagent.
- While Claude Code delegates a job to Codex through Git Bash, I want to follow the Codex run in the same panel, including Codex's own child agents.
- From a file in the session, I want to identify which agent read or changed it, open the current file, and see the historical change when a patch was recorded.
- Across repos and days, I want to compare local Claude and Codex usage and see how close each provider's account is to resetting or reaching a limit.
- I want to start or continue a Claude conversation from the sidebar, send messages and attachments, handle permission requests, and use the Claude Code configuration and workflows I already rely on.
- I want to choose the model and reasoning effort for Claude and Codex, see what each turn actually used, and manage both sign-ins from Agent Lens.
- I want to start, resume, and stop Codex from the same interface and add other agents without changing how I browse, chat, or inspect usage.

The product and display name are **Agent Lens**. The implementation target is <code>D:\Documents\Dev\Saleh Shakib\personal\agent-lens</code>, branch <code>main</code>, with an initial <code>README.md</code>. The planning handoff copies this document into that repository. The initial platform is local Windows 11 with VS Code Desktop. **M1** is viewing, **M2** is Claude Code chat and account control, **M3** is Codex control and chat where supported, and **M4** adds agents through the common adapter contract. ### Shared identities and attribution

| Entity | Identity and purpose |
| --- | --- |
| Project | Canonical local repo root if verified, otherwise canonical recorded cwd or a stable unresolved key. Keep different worktrees distinct and expose an optional common repository grouping. Label remote or missing paths without treating them as locally openable. |
| Session | <code>(provider, sourceHome, session/thread ID)</code>. Provider and local home distinguish the stores. A session carries title, repo/cwd, source, timestamps, identity evidence, active lane summaries, and coverage flags. |
| Lane and turn | Claude main/child lane by session and agent ID, or Codex thread plus parent identity. Each lane owns its turns and request identities. Claude turns follow genuine prompts and explicit branch ancestry. Codex keeps emitted turn IDs. |
| Timeline item and tool run | Stable lane-scoped source identity, timestamp, record order, category, optional sanitized body reference, and result evidence. Tool calls have an explicit call key and pair with results even when the result is written before another related record. |
| Delegation link | External relationship from a Claude lane and Bash call/task to a Codex thread and, when known, its exact turn. Carries confidence, launch role, and observed time. It does not change the provider's canonical session or usage identity. |
| File action and usage sample | Derived observations annotated with provider, project, lane, turn, source evidence and confidence. Keep usage response/snapshot IDs and recorded scope so rollups can be idempotent. |

Build a Claude session catalog using filename/session ID and session root. Merge identity metadata from valid records and use their <code>cwd</code> and <code>gitBranch</code>. When titles are absent, use the first attributable prompt, then a safe <code>lastPrompt</code> fallback and finally a compact session label. Resolve the effective model from <code>assistant.message.model</code> and effort from <code>perTurnEffort</code> or <code>effort</code>. Keep metadata-only rows visible while opening histories lazily. In the transcript, separate a genuine human prompt from a user-shaped tool result, injected reminder, compaction summary, or queue copy. Preserve other branches when present and identify the current branch only when leaf or ancestry evidence supports it.

Claude assistant items may be split into records sharing <code>message.id</code>. Retain each distinct block using <code>uuid</code> and <code>apiBlockIndex</code> where present. Use <code>parentUuid</code> for explicit ancestry, ordering all native records by source offset within each lane. The mixed timeline merges lane timestamps stably and exposes lanes for a precise view. Scope <code>tool_use.id</code> and <code>tool_result.tool_use_id</code> to a session/lane, with an indexed session-wide lookup for explicitly cross-lane references. Never infer a child solely from <code>isSidechain</code>.

### Codex identity, title, repo, model, and usage

- **Thread and agent identity.** Keep a separate identity for each file-backed thread. Build parent-child links from explicit metadata and <code>SubAgentActivity.agent_thread_id</code>. When the child arrives first, show it under an unresolved agent group until the parent appears. Guard against cycles and repeated metadata. Set a child history boundary only after a fixture establishes ordinal semantics for <code>subagent_history_start_ordinal</code>. Use explicit event attribution to avoid presenting copied parent context as fresh child activity. An agent path or nickname is display metadata. A child can share the parent's OS process.
- **Title.** Prefer the newest nonempty, sanitized <code>session_index.thread_name</code>, then the first genuine user prompt's first meaningful line, then a short thread label. For a pasted work order, prefer its first meaningful heading. Keep a generated title stable once selected. Render the source separately as Panel, External CLI, VS Code, or another observed source. A CLI originator by itself cannot prove which orchestrator invoked it.
- **Repo.** Keep <code>session_meta.cwd</code> as the recorded root and show an explicit turn-level <code>cwd</code> change when present. Group by canonical local repo root where it can be resolved safely, otherwise by normalized recorded cwd. Handle drive-letter case, slashes, spaces, missing drives, and linked worktrees. Use local path identity for filtering, so equal folder names on different drives remain distinct. Show a shortened local path and optional branch. Avoid remote URL access.
- **Model and reasoning effort.** Prefer the selected turn's <code>turn_context.model</code> and <code>turn_context.effort</code>. Fall back to applicable <code>thread_settings</code>, then collaboration settings if scoped to that turn. Show requested model and effort as pending until the CLI records effective values. Unknown remains unknown, and one resume can change either value.
- **Tokens.** Usage objects expose <code>input_tokens</code>, <code>cached_input_tokens</code>, <code>cache_write_input_tokens</code>, <code>output_tokens</code>, <code>reasoning_output_tokens</code>, and <code>total_tokens</code> when available. Use the latest <code>turn_token_usage</code> and <code>thread_token_usage</code> for their labeled scopes. Deduplicate per-response <code>usage</code> by thread, turn, and <code>response_id</code>. Never sum cumulative snapshots or add cached and reasoning counts onto the emitted total. The aggregate survey found <code>usage.total_tokens</code> equal to input plus output where present. Fallback <code>event_msg/token_count.info.total_token_usage</code> should be labeled as the reported scope, with <code>last_token_usage</code> labeled Last response. For extension-started runs, use stdout <code>turn.completed.usage</code> as a turn fallback. Preserve unknown fields as unavailable. Parent and child totals stay separately labeled until aggregation semantics are verified.
- **Duration.** Use <code>duration_ms</code> when emitted. For live elapsed time, use validated <code>started_at</code> or the envelope timestamp. Observed lifecycle start integers were epoch seconds. Item timestamps ending in <code>_ms</code> are separate. Fall back to elapsed wall time between recorded boundaries. Pause display updates when the panel is hidden, and label incomplete duration when an end is missing.

### Provider-aware lifecycle

Use a turn state machine plus a separate writer or process state. Key state by <code>(thread_id, turn_id)</code> when possible. Associate ID-less legacy records with an open turn only when unambiguous. Detect each resume as a new turn in the same session.

| UI state | Evidence and precedence |
| --- | --- |
| Starting | A panel-launched process is spawning or connected before its first turn. Show it as a temporary row until stdout or the matching rollout establishes thread identity. |
| Live | A task has started and lacks a terminal record, plus an owned active process, recent relevant record activity, or a correlated writer marker. A marker with no fresh activity is weaker evidence and gets a possible-live/writer-present indicator. Start with a 30-second recent-activity threshold and test against silent long-running commands. A held writer in a shared app can be idle. |
| Completed | A matching <code>task_complete</code> with no error or a correlated stdout <code>turn.completed</code>. A successful process exit without a terminal record gets an explanatory ended status with incomplete history. |
| Failed | <code>task_complete.error</code>, a terminal stdout <code>turn.failed</code>, or a nonzero owned process exit outside an acknowledged Stop. A generic stdout <code>error</code> can be recoverable. A command failure, tool failure, retry, or quota observation by itself leaves the turn active. An explicit terminal failure wins if sources disagree. |
| Interrupted / Aborted | A matching <code>turn_aborted</code>, or a verified operating-system exit after an Agent Lens Stop request when the rollout ends without a terminal record. Show forced termination if used. If a natural completion wins the race, display the natural outcome. |
| Outcome unknown / Recorded | An incomplete historical turn with no writer evidence becomes Outcome unknown. A metadata-only session without a usable lifecycle is Recorded. Reconcile late events and never turn age alone into failure. |

The table above describes Codex. Claude needs a separate reducer with one state for the session being open and another for work in a turn or background lane.

| Claude state | Evidence and precedence |
| --- | --- |
| Active | Fresh attributable prompt, assistant response, open matching tool call, or confirmed running child/task. A fresh local process marker can corroborate running status. Quiet time during a tool does not establish failure. |
| Waiting or idle | A fresh process marker with a supported waiting/idle value or a terminal assistant response while the session remains open. An idle main lane can coexist with running background children. |
| Turn completed | Await the attributed assistant response with a recognized terminal <code>message.stop_reason</code>, resolved relevant synchronous tools, and no stronger error or interruption signal. A <code>tool_use</code> stop reason marks a model step, not completion of the turn. Show background work independently. |
| Child completed or stopped | Observe the child's metadata <code>finished</code>/<code>stoppedByUser</code>, resolved Agent result, or matched terminal task status. A successful initial launch of a background Agent/Bash task leaves the lane active. |
| Failed or interrupted | Use explicit per-lane terminal task status, stop evidence, or a conclusively terminal error. An API error that may retry and a tool error stay row-level until terminal evidence arrives. |
| Recorded or outcome unknown | Incomplete older activity or stale marker, without reliable current evidence. Never terminate, resume, or alert on a guessed live or final state. |

Show a combined root badge if a verified descendant is active and label the main lane separately. Keep idle sessions out of Live when only an idle writer/marker is present. Notify once for observed root turn transitions from live to confirmed completion or failure after activation. Suppress historical discovery toasts and child toasts by default. Allow a scope preference and deduplicate across windows where feasible. Quota alerts use a separate path.

### Discovery and incremental tailing

1. Resolve and validate allowlisted Claude and Codex roots independently. Subscribe to change hints before the initial scan and reconcile hints received during enumeration. Skip symlinks and directory junctions that escape approved roots. Enforce path pattern and provider ID checks. Enumerate Claude projects and session directories and Codex date directories with bounded concurrency. Prioritize recent files, matching liveness markers, and selected or active lanes. Build the sidebar from lightweight metadata/head/tail reads. Defer full replay and usage backfill for older sessions to a background queue.
2. Start with Node <code>fs.watch</code> on Claude projects and Codex sessions in recursive mode. Watch small metadata roots such as the Codex index parent and lock directory separately, and subscribe to known active Claude task directories and the opted-in bridge location. Avoid one watcher per transcript or scanning the whole temporary directory. Treat <code>change</code> and <code>rename</code> as hints. The filename can be absent, events can collapse, a moved directory can stop reporting, and deletion on Windows can yield <code>EPERM</code>. A missing or ambiguous filename schedules a scoped rescan. Rebuild a failed watcher after a re-stat with backoff.
3. Debounce bursts, re-stat, and enqueue one reader per file generation. Poll independently. Initial targets are 500–1,000 ms for selected/live files, 2–5 seconds for recent discovery and relevant metadata when the view is active, and a bounded slower sweep of known older files and folders. Back off when idle. Reconcile after sleep, project changes, midnight rollover, resume in an old folder, and the appearance of a previously missing source root. Reread small replaced metadata atomically by file generation. Keep task prefix probes bounded and watch temporary files only while evidence is relevant.
4. Track absolute byte offset, generation identity, preceding bounded overlap where useful, and pending bytes after the last newline. Read appended chunks with positional I/O. Split on LF in bytes, strip CR for CRLF, handle an initial BOM, then decode complete UTF-8 lines. A multi-byte character, JSON escape, or partial object may span reads. Preserve the final partial line for a subsequent append. Optionally accept a valid newline-less final object once a stable ended file has been verified. Establish a committed offset for complete lines and keep the pending bytes bounded.
5. When identity changes, the file shrinks, or an overlap check detects a rewrite, reset that generation, reparse and reconcile by thread identity. Track <code>dev</code>/<code>ino</code> when meaningful, size and creation metadata, and a bounded content check as needed. A changed offset defines a replay, so do not append the replacement history to the old view. Handle access denied, sharing violations, and transient disappearance as retryable read state. Never create a missing file or retain handles that unnecessarily impede writer cleanup. [Node filesystem watch caveats](https://nodejs.org/download/release/v22.13.0/docs/api/fs.html#caveats)

### Parsing, merging, and resource budgets

- Use small type guards at provider adapter boundaries. For syntactically invalid complete lines, increment a diagnostics count and continue. Quarantine malformed nested arguments to a generic tool row. Recognize legacy variants by shape and track the emitter version for compatibility diagnostics. Unknown types can produce a bounded count with a safe type label. Do not log the line, unknown payload, exception text that embeds content, or unknown data keys.
- Read in chunks, initially 64–256 KiB. Set a configurable internal ceiling of 16 MiB per JSON record for the first implementation, with a diagnostic placeholder and a discard-until-newline mode for bigger records. That includes the largest observed record while capping allocation. Parse large lines off the extension-host event loop if profiling shows stalls. Discard ignored context and duplicate embedded history as soon as the record is classified. Treat these figures as initial budgets to verify.
- Pair Claude blocks and results through their explicit IDs, grouping provider responses while preserving each block. Pair Codex function/custom outputs by <code>(thread, turn, call_id)</code>. Match a structured <code>item.id</code> to an explicit equivalent ID when available. An otherwise unique match can use kind, turn, command or text, and occurrence order. Many observed Codex IDs did not match verbatim. When matching is ambiguous, retain the structured row and group available sanitized details under a collapsed turn section without merging unrelated executions.
- For a panel-owned worker, register the <code>thread.started.thread_id</code> when stdout provides it. For resume, the expected ID is already known. A mismatch blocks control and surfaces an explicit diagnostic. Adapt <code>turn.started</code>, <code>turn.completed.usage</code>, <code>turn.failed</code>, <code>error</code>, and <code>item.started</code>/<code>item.updated</code>/<code>item.completed</code> to a provisional stream. Use stream-scoped identities and monotonic local sequence. Merge by explicit IDs when available, otherwise match uniquely by content and ordinal within the same turn. Avoid sending duplicate cards as stdout and rollout catch up. Enable live updates only at the granularity the stream actually emits. External rollouts often emit completed records, so individual command output may appear when Codex writes the result.
- Use file order as authoritative within a rollout and explicit relations across files. For mixed agent views, use event time with deterministic tie-breaks and preserve each thread's internal order. A late child or matched tool result updates its row without changing the scroll anchor.
- Batch updates about every 75–150 ms when visible. Retain row summaries and positions for older pages, evict large bodies, and fetch sanitized body data lazily. Keep the most recently selected sessions in a bounded cache and keep only lifecycle summaries for other sessions. Use pages of roughly 100 rows plus an overscan window for long timelines. Cap initial previews and load longer text or hunks by page. Do not precompute every repo diff or keep an entire historical directory in memory.
- Schedule usage backfill and file-index enrichment behind live observation, with per-cycle time/IO budgets and resumable progress within an extension session. Store sparse record locations and bounded summaries instead of raw text. Keep daily/project summaries as the ledger compacts and compute drilldowns lazily. Track which files and generations reached committed offsets so a replacement can invalidate and rebuild affected aggregates without double counting.
- Targets on the reference machine are first sidebar rows within one second from a warm start, normally visible append updates within two seconds, and smooth scroll on a 1.2 MB session. Profile 8 MiB records, a 42 MiB Claude transcript, and dozens of live lanes alongside discovery of 1,800-plus child files. Check responsiveness during quota backfill and verify polling fallback cadence. These are implementation targets.

## 9. M2 Chat

The second milestone replaces the user's daily Claude Code VS Code panel workflow. Chat is a first-class capability in the shared session panel. ### Composer and session flow

1. **Start or continue.** New chat chooses a local project, adapter, profile and supported model/effort settings. Continue resolves the sidebar row to the exact Claude session ID, owning profile and recorded workspace. Support every compatible local main session the sidebar shows, whether it originated in Agent Lens, Claude's panel or a terminal. For a missing repo, different account profile or concurrently active owner, show the specific condition and preserve the draft. Select the correct subtree/profile before resuming. Never guess a session from its title or automatically fork it.
2. **Send.** Keep an editor-sized multiline draft with Send or Queue, model and effort, optional Fast or permission mode, and attachment chips. Display adapter-supplied effective values next to the picker. A pending bubble has a local message ID. Turn it into the canonical prompt on a valid stream acknowledgment or unique transcript match. Preserve a failed or unsent draft. An unconfirmed send after host restart requires a check or explicit retry rather than resubmission.
3. **Stream.** Turn provider text blocks and partial deltas into progressive rows with stable IDs. Group visible thinking and approved progress separately from the final response, and discard signatures and encrypted/internal payloads. Use tool call/result, subagent identity, and task progress for live lane updates. Follow the same safe output limits and scroll behavior as the history timeline. Map stdout and transcript copies into the same row; keep append-only observation available if streaming reconnects late.
4. **Queue.** Allow the user to add, edit, or remove one or more drafts while a turn runs. The default local queue is FIFO and sends the next message only at a confirmed eligible turn boundary. Live steering is an independent action where a provider exposes and verifies it. Show the applied model and attachment set for each queued draft. ## 14. Security and privacy

- Use read-only handles for eligible Claude transcripts, agent metadata, task/spill outputs, opted-in quota snapshots, and Codex rollouts and index. Inspect lock filenames and metadata in watch mode. Exclude credential, secret, sandbox-secret, general history and operational database paths. A dedicated Codex model reader may project a minimal allowlist from its model cache and model-related config/profile fields in §11. Keep general provider configuration and credential storage outside the transcript reader. Canonicalize approved roots, reject paths or reparse points escaping them, and revalidate user-invoked file or repo actions. Scope task/spill output to the owning session.
- Allowlist known schema fields before producing view data. Drop Claude request payloads and credential/organization attachments and Codex account-scoped metadata, along with credentials, injected instructions, encrypted/raw reasoning, raw tool schemas, connector identifiers, and opaque tool bodies. Redact recognizable secrets and sensitive path references in all text before it reaches the webview, clipboard, notifications, or diagnostic interfaces. Apply the same boundary to stdout/stderr, prices and quota bridge metadata, and errors. Suppress command, output, diff and file actions tied to sensitive locations or unsafe payloads. Arbitrary free text can contain unlabeled secrets that pattern matching cannot identify. Provide a private display mode that suppresses free-form payloads and always keep raw payloads out of diagnostics.
- Render content through text nodes and narrowly scoped markup generated by the extension. Parse recorded diff hunks without applying them. Strip ANSI/OSC control codes. Keep remote images, arbitrary command links, executable HTML, and inline untrusted markup out of the UI. Use a webview CSP with <code>default-src 'none'</code>, <code>connect-src 'none'</code>, and nonce-approved bundled scripts plus narrowly scoped local stylesheet and asset origins. Use <code>asWebviewUri</code> and restrict <code>localResourceRoots</code> to packaged assets. [VS Code webview security](https://code.visualstudio.com/api/extension-guides/webview#security)
- M1 observation makes no network calls and has no telemetry or remote assets. Use the optional status-line relay and documented read-only auth probes only within their verified local scope. User-launched agents and official sign-in flows use their configured providers. Keep credentials, OAuth, API keys and authentication traffic within the provider's documented tools and environment. Avoid capturing official login terminal output.
- Store minimal local preferences, navigation state, price table and opt-in quota snapshots. Content caches, composer drafts, queued messages, and account details are memory-only by default. Keep roots, CLI selection, source profiles and launch policy in user or machine settings, outside repo-controlled configuration. Use VS Code Workspace Trust to gate agent execution and interactive approval. Redacted, read-only navigation can remain available in Restricted Mode. [VS Code Workspace Trust](https://code.visualstudio.com/api/extension-guides/workspace-trust)
- Treat webviews and provider records as untrusted inputs. Validate message shape, adapter/account scope, owner, capability, current turn, and trusted repo at the host boundary. Bind approval to a live request. A historical log message cannot start, approve, authenticate, or stop a process. Limit a native approval bridge to an owned local stdio or vetted Windows IPC channel. Close or reject requests when the owner or channel changes. A user Stop action names the verified target and labels graceful and forced behaviors separately.
